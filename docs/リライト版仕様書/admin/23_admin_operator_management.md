## 1. 文書目的

- 本書は、オペレーター管理の要件を定義する。
- 全画面に共通する権限、UI 規則、監査ログ、通知、用語は共通編を参照する。本書は本画面に固有の要件を扱う。
- オペレーターの作業件数・正答率の詳細な集計は `24_admin_achievements.md` で扱う。本画面は詳細モーダル内の簡易集計（§4.8）のみを持つ。

## 2. 画面概要

- 作業者アカウント（Lv1〜Lv4）を、招待から無効化まで単一の画面で管理する。
- 「誰が・どこで・何を担当できるか」を決める画面であり、所属グループ、権限レベル、対応可能言語を設定する。
- 招待中のアカウントも一覧に混在して表示する。招待の状態を別領域に分けない。
- 個別のアカウントに対する確認と操作はモーダルで完結する。

## 3. 想定利用者と対象範囲

### 3.1 想定利用者

- 自グループの作業者を管理する Lv2（OperatorAdmin）。配下アカウントの招待、権限・所属の設定を行う。
- 運営全体を管理する Lv3・Lv4。全グループのアカウントとグループそのものを管理する。

### 3.2 対象範囲

- オペレーターアカウントの一覧・検索・絞り込み
- アカウントの招待、編集、有効化・無効化
- 所属グループ、権限レベル、対応可能言語の設定
- パスワードの初期化と管理者による直接設定
- グループ（会社・法人単位）の作成

### 3.3 対象外

- オペレーター別の作業件数・正答率・報酬の詳細な集計（`24_admin_achievements.md`。当月分の簡易集計のみ §4.8 で本画面が持つ）
- 利用者（顧客側）アカウントの管理（`11_admin_user_management.md`）
- 全画面横断の監査ログ閲覧（`25_admin_audit_log.md`）

## 4. 画面要件

### 4.1 共通構成

- ヘッダー、サイドバー、パンくずを表示する（`01_admin_common_ui.md` §2）。
- 画面タイトルを表示する。
- 画面は上から、検索・絞り込み条件、オペレーター一覧の順に配置する。
- 一覧の上部に、新規招待とグループ作成の操作を配置する。

### 4.2 一覧表示

各オペレーターについて次を表示する。

| 表示項目 | 内容 |
| --- | --- |
| オペレーター ID | アカウントを一意に識別する ID |
| 氏名 | アカウントの氏名 |
| メールアドレス | ログインおよび通知の宛先 |
| 所属グループ | 所属する会社・法人 |
| 権限レベル | Lv1〜Lv4 |
| 作成日時 | アカウントを作成した日時（現行画面の表示項目） |
| ステータス | 有効 / 無効 / 招待中 |
| 最終ログイン日時 | 最後にログインした日時 |

- 招待中のアカウントは、有効・無効のアカウントと同一の一覧に表示する。
- 最終ログイン日時が存在しないアカウントは「—」を表示する（`01_admin_common_ui.md` §9）。
- 一覧はページングと表示件数の選択に対応する（`01_admin_common_ui.md` §4.3）。
- 各列で昇順・降順の並び替えができる。

### 4.3 検索・絞り込み

| 条件 | 種別 | 内容 |
| --- | --- | --- |
| 氏名・メールアドレス・オペレーター ID | 検索 | 部分一致で対象を絞り込む |
| 所属グループ | 絞り込み | 登録済みのグループから選択する。初期値は「すべて」 |
| 権限レベル | 絞り込み | Lv1〜Lv4 から選択する。初期値は「すべて」 |
| ステータス | 絞り込み | 有効 / 無効 / 招待中 から選択する。初期値は「すべて」 |
| 対応可能言語 | 絞り込み | 言語マスタから選択する。初期値は「すべて」。設定値そのものは詳細モーダル（§4.4）で確認する（2026-08-28 のモックレビューで一覧の表示項目から対応可能言語を外し、絞り込み条件のみ維持とした） |

条件をまとめて初期状態へ戻す操作を用意する。

### 4.4 詳細モーダル

一覧から対象を選択すると詳細モーダルを開く。独立した詳細画面は設けない。モーダルには押下した行のオペレーターを表示する（`01_admin_common_ui.md` §6）。

モーダルは次で構成する。

| 領域 | 内容 |
| --- | --- |
| アカウント情報 | 氏名・メールアドレス（編集可）と、オペレーター ID・登録日時・最終ログイン日時（表示のみ） |
| 設定 | 所属グループ、権限レベル、対応可能言語、ステータスの変更 |
| パスワード操作 | 初期化メールの送信、管理者による直接設定（§4.6） |
| 招待操作 | 招待中のアカウントに対する再送・キャンセル（§4.5） |
| 簡易集計 | 当月の作業件数・正答率・スキップ率（§4.8） |
| 実績への導線 | オペレーター実績確認（SCR-A-015）の当該オペレーターの集計へ遷移する。対象のオペレーターで絞り込んだ状態で開く（`01_admin_common_ui.md` §4.1.1） |

モーダル内で変更した内容は、閉じた後の一覧へ反映する（`01_admin_common_ui.md` §6）。

権限レベルとステータスの変更に、操作者と対象の権限レベルの上下関係による制約は設けない（2026-08-28 のモックレビューで確定）。

- 本画面にアクセスできる Lv2 以上は、自身を含む任意の対象アカウントへ Lv1〜Lv4 のいずれの権限レベルも設定できる。操作できるアカウントの範囲は §6 のデータ範囲に従う。
- 自身の権限レベルを引き下げた場合、以後の画面アクセスと操作は変更後の権限レベルに従う。
- 所属グループ・権限レベル・ステータスは、開いた対象の現在の値を初期表示する。
- 招待で付与できる権限レベルも制限せず、Lv1〜Lv4 から選択する（§4.5）。
- メールアドレスの変更は、既存アカウント（招待中を含む）と重複しないことを保存前に確認する。

### 4.5 招待

- 招待はメールアドレスを指定して実行する。実行時に所属グループ、権限レベル、対応可能言語を設定する。
- 招待を実行すると仮アカウントを作成し、ステータスを「招待中」とする。
- 招待メールに含める登録リンクの有効期限は発行から 72 時間とする。
- 招待中のアカウントに対して、招待メールの再送とキャンセルを実行できる。再送時は新しいリンクを発行し、有効期限を再度 72 時間とする。
- 本人が登録を完了するとステータスは「有効」へ移る。

詳細は `00_admin_common_permissions.md` §7.2 に従う。

### 4.6 パスワード管理

| 系統 | 実行できる権限 | 動作 |
| --- | --- | --- |
| 初期化メールの送信 | Lv2 以上（自身の操作範囲内） | 対象本人へ初期化メールを送信し、本人が新しいパスワードを設定する |
| 管理者による直接設定 | Lv4 のみ | 管理者が新しいパスワードを直接設定する。理由の入力を必須とし、実行後に対象本人へ通知メールを送信する |

- 直接設定は確認ダイアログ内で理由を入力する（`01_admin_common_ui.md` §7.2）。入力した理由は監査ログに記録する。
- Lv4 以外には直接設定の操作要素を表示しない。

### 4.7 ステータスの変更

- ステータスは有効・無効・招待中の 3 値とする（`04_admin_common_glossary.md` §6.1）。
- 詳細モーダルから手動で変更できるのは、有効と無効の相互変更に限る。
- 「招待中」は招待の実行により開始し、本人の登録完了をもって有効へ移るシステム管理の状態とする（§7.3）。ステータスの変更先の選択肢には含めない。
- 稼働を停止するアカウントは無効へ変更する。退職者も無効で管理する。
- 無効へ変更する際は確認ダイアログを表示する（`01_admin_common_ui.md` §7.1）。
- 無効のアカウントはログインできない。作業の出題対象からも外れる。
- 無効から有効へ戻すことができる。

状態別に実行できる操作を次のとおりとする。「アカウント情報の編集」は氏名・メールアドレス・所属グループ・権限レベル・対応可能言語の変更を指す。

| 状態 | アカウント情報の編集 | ステータスの手動変更 | 招待の再送 | 招待のキャンセル | パスワード操作 |
| --- | --- | --- | --- | --- | --- |
| 有効 | 可 | 無効へ変更する | 不可 | 不可 | 可 |
| 無効 | 可 | 有効へ変更する | 不可 | 不可 | 不可 |
| 招待中 | 所属グループ・権限レベル・対応可能言語のみ可 | 不可 | 可 | 可 | 不可 |

無効と招待中のアカウントはログインできる状態にないため、パスワード操作の対象としない。招待中のアカウントのパスワードは、本人が登録を完了する時点で設定する（§4.5）。

本画面はアカウントの削除操作を持たず、稼働の停止を無効化で表す方針を採る。内部的な論理削除フラグは別に管理し、本画面からは操作しない。

### 4.8 簡易集計

- 詳細モーダル内に、当該オペレーターの当月の集計を数値カードで表示する（2026-08-28 のモックレビューで追加）。
- 表示する指標は作業件数・正答率・スキップ率の 3 つとする。作業件数・正答率の定義は `24_admin_achievements.md` §4.3 と同一とし、値も同じデータを参照して一致させる。
- スキップ率は「スキップ回数 ÷（作業件数 + スキップ回数）」とし、整数の百分率で表示する（※要確定・§11 の #14）。
- 集計対象の実績が存在しないオペレーター（招待中を含む）は「—」を表示する（`01_admin_common_ui.md` §9）。
- 期間指定や内訳を含む詳細な集計は、実績への導線（§4.4）からオペレーター実績確認（SCR-A-015）で確認する。

### 4.9 グループ管理

- グループ（会社・法人単位）の作成は Lv3 以上が行う。
- グループには名称を設定する。作成したグループは §4.3 の所属グループの選択肢および §4.4 の設定で選択できる。

### 4.10 対応可能言語

- 対応可能言語は DB のマスタで管理する。本画面ではマスタに登録済みの言語から複数を選択して設定する。
- 言語マスタへの追加・変更は開発側が DB を直接更新する運用とする。
- 対応可能言語は出題を制限するものではない。データ入力対象一覧（SCR-A-009）の対象言語が「自動」のときの対象を決める既定値として働き、オペレーターは対応可能言語の外の言語も自分で選べる（`19_admin_data_input_list.md` §4.2）。
- 言語非依存の作業グループ（`20_admin_data_input_form.md` §4.4 の①・⑤・⑥）は、対応可能言語に関わらず全オペレーターへ出題する。入力値が名刺の言語に左右されないためである。

参考: 現行画面 `/admin/operator_list` の新規登録では、日本語・英語・中国語簡体字・中国語繁体字の複数選択が可能である。

### 4.11 追加要件（あったほうが良い）

| 要件 | 内容 |
| --- | --- |
| グループの編集・削除 | 作成済みグループの名称変更と削除。削除時の所属アカウントの扱いは §11 で確定する |

## 5. 通知

本画面の操作を起点として次の通知が発火する（`03_admin_common_notifications.md` §2）。

| 契機 | 通知 | 宛先 |
| --- | --- | --- |
| 招待を実行したとき | オペレーター招待メール | 招待先のメールアドレス |
| 招待を再送したとき | オペレーター招待メール（再送） | 招待先のメールアドレス |
| パスワード初期化を実行したとき | パスワード初期化メール | 対象アカウントの本人 |
| Lv4 がパスワードを直接設定したとき | パスワード変更の本人通知 | 対象アカウントの本人 |

パスワード変更の本人通知は、送信の要否を管理者が選択する形にはしない。

## 6. 権限とデータ範囲

| 権限レベル | 扱い |
| --- | --- |
| Lv1 | 本画面へアクセスできない。サイドバーに項目を表示しない |
| Lv2 | 自グループの全アカウント（権限レベルを問わない）を表示・操作できる |
| Lv3 | 全グループのアカウントを表示・操作できる。グループを作成できる |
| Lv4 | 全グループのアカウントを表示・操作できる。グループを作成できる。パスワードの直接設定を実行できる |

- 権限判定とデータ範囲の絞り込みはサーバー側で行う（`00_admin_common_permissions.md` §9.1）。
- 操作の実行可否はデータ範囲のみで決まる。範囲内の対象であれば、権限レベルの上下に関わらず §4.4 の変更を実行できる（2026-08-28 確定）。

## 7. 状態と挙動

### 7.1 初期表示

- 検索条件は未入力、各絞り込みは「すべて」の状態で表示する。
- 一覧の既定の並び順はオペレーター ID の昇順とする。
- 表示件数の既定は 50 件とする。

### 7.2 該当が 0 件の場合

- 一覧の位置に該当なしの旨を表示する。

### 7.3 招待の完了

- 本人が登録を完了すると、一覧上のステータスが「招待中」から「有効」へ変わる。
- 招待をキャンセルすると仮アカウントは招待前の状態へ戻り、発行済みリンクは無効になる。

### 7.4 権限レベル・所属の変更

- 権限レベルまたは所属グループを変更すると、変更後の範囲で画面表示とデータ範囲が決まる。
- 所属グループの変更は、変更後に行った作業の実績から反映する。変更前に行った作業実績をどちらのグループへ集計するかは `24_admin_achievements.md` §11 の #11 で確定する。
- 変更対象のアカウントが持つ既存セッションの扱いは `00_admin_common_permissions.md` §10 の #8 で確定する。

### 7.5 操作の記録

次の操作は監査ログに記録する（`02_admin_common_audit_log.md` §3）。

- パスワードの管理者直接設定（理由を含む）
- パスワード初期化メールの送信
- 権限レベルの変更
- アカウントの有効化・無効化
- 招待の実行・再送・キャンセル
- グループの作成
- 氏名・メールアドレスの変更（※要確定・§11 の #15）

## 8. 現行画面からの引き継ぎ

現行画面 `/admin/operator_list` は次を備える。本画面はこれらの機能を引き継ぐ最低線とする。

| 現行の機能 | 本書での扱い |
| --- | --- |
| オペレーター一覧（全列で並び替え可能） | §4.2 |
| 検索 | §4.3 |
| 新規登録（対応言語は日本語・英語・中国語簡体字・中国語繁体字の複数選択） | §4.5、§4.10。登録は招待による方式へ変更する |
| 編集 | §4.4 |
| アカウントの停止 | §4.7。無効化として扱う |

現行画面の所属は会社・法人単位ではなくチーム A / B / C 単位で管理されている。本書は会社・法人単位のグループを前提とする。移行方針は §11 で確定する。

参考: 現行モック `03_admin/operator-management.html` は、氏名・メール・ID による検索、グループ・権限・状態・言語による絞り込み、詳細モーダル（氏名・メールを含む設定変更・パスワード操作・当月の簡易集計）を持つ。一括操作は持たない（2026-08-28 時点）。モックは仕様上の正解とは扱わない。

## 10. 画面確認観点

モックアップ上で次を確認する。

- [ ] Lv1〜Lv4 のアカウントが単一の一覧に表示される
- [ ] 詳細モーダルの氏名・メールアドレス・所属グループ・権限レベル・ステータスが、開いた対象の値で表示される
- [ ] 権限レベルの選択肢に Lv1〜Lv4 がすべて表示され、いずれの対象（自分自身・同格以上を含む）にも変更できる
- [ ] 招待中のアカウントが有効・無効のアカウントと同じ一覧に表示される
- [ ] 最終ログイン日時が存在しないアカウントに「—」が表示される
- [ ] 氏名・メールアドレス・オペレーター ID による検索と、グループ・権限レベル・ステータス・対応可能言語による絞り込みが機能する
- [ ] 一覧の各列で並び替えができ、初期表示がオペレーター ID の昇順である
- [ ] 一覧から詳細モーダルが開き、モーダル内で氏名・メールアドレス・所属・権限レベル・対応可能言語・ステータスを変更できる
- [ ] メールアドレスを既存アカウントと重複する値へ変更しようとすると保存できない
- [ ] モーダル内で変更した内容が、閉じた後の一覧へ反映される
- [ ] 招待を実行すると一覧にステータス「招待中」のアカウントが表示される
- [ ] 招待中のアカウントに対して再送とキャンセルの操作が表示される
- [ ] 無効へ変更する際に確認ダイアログが表示される
- [ ] Lv4 以外のアカウントで、パスワード直接設定の操作要素が表示されない
- [ ] Lv4 でパスワードを直接設定する際、確認ダイアログ内で理由入力が必須になる
- [ ] グループを作成でき、作成したグループが所属グループの選択肢に現れる
- [ ] 詳細モーダル内の簡易集計に当月の作業件数・正答率・スキップ率が表示され、実績のないオペレーターでは「—」が表示される
