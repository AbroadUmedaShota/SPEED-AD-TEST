## 1. 文書目的

- 本書は、監査ログ画面（記録の横断ビュー）の要件を定義する。本画面は新設である。
- 記録対象の操作、記録項目、記録の取り扱いの方針は `02_admin_common_audit_log.md` で定義する。本書はそれらを表示・検索・出力する画面の要件を扱う。方針を本書で再定義しない。
- 各画面の詳細内に配置する個別ログは、それぞれの画面別ファイルで扱う。

## 2. 画面概要

- 運営側が行った操作を「誰が・いつ・何に対して」の形で横断的に確認する画面。
- 記録は追記のみとし、画面から編集・削除は行わない。
- 抽出した記録をファイルとして出力する。
- 本画面と各画面の詳細内に配置する個別ログは、同一のデータを参照する。抽出条件のみが異なる。

## 3. 想定利用者と対象範囲

### 3.1 想定利用者

- 運営全体を管理する Lv3・Lv4。顧客からの問い合わせ、データの不整合、権限の変更経緯を追跡する。

### 3.2 対象範囲

- 記録の一覧表示
- 検索・絞り込み
- ファイル出力

### 3.3 対象外

- 記録対象の操作と記録項目の定義（`02_admin_common_audit_log.md`）
- 各画面の詳細内に配置する個別ログの表示（各画面別ファイル）
- 利用者自身が行った操作の履歴
- サーバーのアクセスログとエラーログ（`05_admin_nonfunctional.md` §4.3・§5）

## 4. 画面要件

### 4.1 共通構成

- ヘッダー、サイドバー、パンくずを表示する（`01_admin_common_ui.md` §2）。
- 画面タイトルを表示する。
- サイドバーから単独で遷移できる位置に配置する。
- 画面は上から、検索・絞り込み条件、記録一覧の順に配置する。

### 4.2 一覧表示

各記録について次を表示する。表示項目の定義は `02_admin_common_audit_log.md` §4 に従う。

| 表示項目 | 内容 |
| --- | --- |
| 操作日時 | 操作を実行した日時 |
| 操作者 | 実行したアカウントの識別子と表示名 |
| 権限レベル | 実行時の権限レベル |
| 操作種別 | 実行した操作の区分 |
| 対象 | 操作対象の識別子と表示名 |
| 対象グループ | 操作対象が属するグループ |
| 理由 | 実行時に入力した理由 |

- 日時は `YYYY/MM/DD HH:MM` で表示する（`01_admin_common_ui.md` §9）。
- 一覧はページングと表示件数の選択に対応する（`01_admin_common_ui.md` §4.3）。
- 記録の編集・削除の操作要素は配置しない。

### 4.3 検索・絞り込み

| 条件 | 種別 | 内容 |
| --- | --- | --- |
| 期間 | 絞り込み | 開始日と終了日を指定する。初期値は直近 7 日間 |
| 操作者 | 検索 | アカウントの識別子または氏名で絞り込む |
| 操作種別 | 絞り込み | `02_admin_common_audit_log.md` §3 の操作から選択する。初期値は「すべて」 |
| 対象 | 検索 | 対象の識別子（ユーザー ID、アンケート ID、オペレーター ID）で絞り込む |
| 対象グループ | 絞り込み | 登録済みのグループから選択する。初期値は「すべて」 |

- 条件をまとめて初期状態へ戻す操作を用意する。
- 検索条件の最終的な構成は §11 で確定する。

### 4.4 並び順

- 一覧の既定の並び順は操作日時の降順とし、直近の操作を先頭に表示する。
- 操作日時の昇順・降順を切り替えられる。

### 4.5 ファイル出力

- 抽出した記録をファイルとして出力する。
- 出力対象は、その時点で適用されている検索条件・絞り込み条件の結果とする。ページングの表示範囲には限定しない。
- 出力形式と文字コードは `01_admin_common_ui.md` §10 に従う。
- 出力操作そのものも記録対象（データ持ち出し）とする（`02_admin_common_audit_log.md` §3）。

### 4.6 追加要件（あったほうが良い）

| 要件 | 内容 |
| --- | --- |
| 変更前後の値の表示 | 変更を伴う操作について、変更前の値と変更後の値を表示する |
| 理由の表示範囲の拡大 | パスワードの管理者直接設定以外の操作についても、入力した理由を表示する |
| 成功・失敗の表示 | 操作が成立したか失敗したかを区別して表示する |

これらは記録側の対応が前提となる（`02_admin_common_audit_log.md` §4.1）。導入の判断は記録項目の確定と連動する。

## 5. 通知

本画面の操作を起点とする通知・メールの発火はない（`03_admin_common_notifications.md` §2）。

## 6. 権限とデータ範囲

| 権限レベル | 扱い |
| --- | --- |
| Lv1 | 本画面へアクセスできない。サイドバーに項目を表示しない |
| Lv2 | 本画面へアクセスできない。サイドバーに項目を表示しない（※要確定・§11） |
| Lv3 | 全範囲の記録を表示・出力できる |
| Lv4 | 全範囲の記録を表示・出力できる |

- 権限判定とデータ範囲の絞り込みはサーバー側で行う（`00_admin_common_permissions.md` §9.1）。
- Lv2 に自グループ分の閲覧を許可するかは確定前とする。許可する場合、対象グループによる絞り込みを自グループに固定する。
- 各画面の詳細内に配置する個別ログは、その画面のアクセス権限とデータ範囲に従う（`02_admin_common_audit_log.md` §6）。

## 7. 状態と挙動

### 7.1 初期表示

- 期間は直近 7 日間、その他の条件は未指定の状態で表示する。
- 操作日時の降順で一覧を表示する。
- 表示件数の既定は 50 件とする。

### 7.2 該当が 0 件の場合

- 一覧の位置に該当なしの旨を表示する。

### 7.3 記録の不変性

- 表示した記録に対する編集・削除は行わない。画面上に該当する操作要素を配置しない。
- 記録の追加は各画面の操作に伴って発生する。本画面から記録を追加する操作は行わない。

### 7.4 個別ログとの一致

- 各画面の詳細内に配置する個別ログに表示される記録は、本画面でも同一の内容で表示される。

## 8. 現行画面からの引き継ぎ

現行に該当する画面は存在しない。本画面は新設として全機能を新たに実装する。

現行のモックにも、運営側操作を横断で確認する画面は存在しない。各画面のモックが持つ「更新ログ」「ステータス遷移ログ」は画面内の個別ログに相当する。

## 10. 画面確認観点

モックアップ上で次を確認する。

- [ ] サイドバーから本画面へ遷移できる
- [ ] 一覧に操作日時・操作者・権限レベル・操作種別・対象・対象グループ・理由が表示される
- [ ] 日時が `YYYY/MM/DD HH:MM` で表示される
- [ ] 期間・操作者・操作種別・対象・対象グループによる絞り込みが機能する
- [ ] 条件をまとめて初期状態へ戻す操作が機能する
- [ ] 初期表示が直近 7 日間、操作日時の降順である
- [ ] 操作日時の昇順・降順を切り替えられる
- [ ] パスワードの管理者直接設定の記録に、入力した理由が表示される
- [ ] 記録の編集・削除の操作要素が画面に存在しない
- [ ] 抽出結果のファイル出力操作を実行できる
- [ ] 各画面の詳細内の個別ログと、本画面に表示される内容が一致する
- [ ] 該当が 0 件のとき、一覧の位置に該当なしの旨が表示される
- [ ] Lv2 以下でログインした場合、本画面の URL へ直接アクセスしても表示されない

## 11. 画面外の確認事項

| # | 項目 | 内容 |
| --- | --- | --- |
| 1 | 保持期間 | 記録をどこまで遡って保持するかを確定する。保持期間経過後の扱い（削除／アーカイブ）と、画面から検索できる範囲を併せて決める。 |
| 2 | Lv2 の閲覧許可 | Lv2 に自グループ分の閲覧を許可するかを確定する。許可する場合、対象グループの絞り込みを自グループへ固定し、`00_admin_common_permissions.md` §3 のアクセス範囲へ Lv2 を追加する。`00_admin_common_permissions.md` §10 の #6、`02_admin_common_audit_log.md` §9 の #2 と同一の論点であり、3 点を同時に確定する。 |
| 3 | 画面 ID の採番 | 本画面の画面 ID を採番する。 |
| 4 | 検索条件の確定 | §4.3 の条件で追跡に足りるかを確定する。IP アドレス、操作の成否を条件に加えるかを含めて決める。 |
| 5 | 変更前後の値の記録 | §4.6 の追加要件を導入するかを確定する。記録側の対応（`02_admin_common_audit_log.md` §9 の #3）と同時に決める。 |
| 6 | 出力の上限 | ファイル出力の対象件数に上限を設けるかを確定する。上限を超える場合の分割出力の要否を決める。 |
| 7 | 利用者側操作との統合 | 利用者が自分で行った変更を本画面で追えるようにするかを確定する。`02_admin_common_audit_log.md` §9 の #6 と同一の論点である。 |
| 8 | 保存先 | 記録を DB テーブルとファイルのいずれで保持するかを確定する。検索性能と保持期間の要件に影響する。 |
