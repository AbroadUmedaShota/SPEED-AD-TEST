## 1. 文書目的

- 本書は、請求管理（全顧客の請求の横断確認）の要件を定義する。
- 全画面に共通する権限、UI 規則、監査ログ、通知、用語は共通編を参照する。本書は本画面に固有の要件を扱う。
- 月次の請求書（アカウントと発行月の組み合わせで作成する書面）は本書の対象外とし、`16_admin_invoice.md` で扱う。本書は請求書管理を別画面とする前提で記述する。1 本化の判断は §11 で扱う。
- クーポンの発行・編集・利用実績の確認は `17_admin_coupon.md` で扱う。

## 2. 画面概要

- 全顧客の請求金額を一覧で把握する画面。
- 請求金額はデータ化件数とプラン単価から算出した値を表示する。金額の調整はクーポン割引の事後適用で行う。
- 請求内容の確認と、クーポン割引の事後適用による金額調整を本画面で完結させる。

### 2.1 請求管理と請求書管理の責務分担

| 画面 | 担当する範囲 |
| --- | --- |
| 請求管理（本画面） | アンケート単位の請求金額の確認とクーポンの事後適用 |
| 請求書管理（未採番） | アカウントと発行月の組み合わせで作成する請求書の確認と内訳表示 |

## 3. 想定利用者と対象範囲

### 3.1 想定利用者

- 運営全体を管理する Lv3・Lv4。請求金額と内訳の確認、クーポン割引の事後適用を行う。

### 3.2 対象範囲

- 請求情報の一覧・検索
- クーポン割引の事後適用
- アンケート情報・アカウント情報への遷移

### 3.3 対象外

- 月次請求書の確認と出力（`16_admin_invoice.md`）
- クーポンの発行・編集・利用実績の集計（`17_admin_coupon.md`）
- アンケートの内容と状態の操作（`13_admin_survey_management.md`）

## 4. 画面要件

### 4.1 共通構成

- ヘッダー、サイドバー、パンくずを表示する（`01_admin_common_ui.md` §2）。
- 画面タイトルを表示する。
- 画面は上から、検索・絞り込み条件、請求一覧の順に配置する。

### 4.2 一覧表示

各請求について次を表示する。

| 表示項目 | 内容 |
| --- | --- |
| 会社名 | 請求先の会社 |
| グループ | 対象アンケートを共同編集するグループ。グループに属さないアンケートでは表示しない |
| 氏名 | 請求先の利用者 |
| 作業ステータス | 対象アンケートの名刺データ化の進み具合 |
| 請求金額 | 請求する金額（§7.2 の算出値） |
| 実際の件数 | 名刺データ化を実施した件数 |
| 単価 | 1 件あたりの単価。データ化申込プランごとに定まる（`04_admin_common_glossary.md` §4） |
| クーポン割引率 | 適用したクーポンの割引率 |
| クーポンメモ | 適用したクーポンに関する記録 |
| 請求日 | 請求を発行した日付 |
| 支払期日 | 支払いの期限。既定は締め支払いの規則（§4.5）から算出する |
| データ化完了予定日 | 名刺データ化の完了予定日 |

- 金額と単価は 3 桁ごとのカンマ区切りで表示し、単位を「円」とする（`01_admin_common_ui.md` §9）。
- 割引率は整数の百分率で表示する。
- 会社名はユーザー詳細（SCR-A-003）へのリンクとし、請求先のアカウント情報を確認できるようにする。
- グループが設定されているアンケートは、会社名の位置にグループ名を出し、グループである旨が分かる表示を添える。会社名は補助として併記する。グループはアンケートを複数名で共同編集する単位であり（`user/05_group_edit_requirements.md` §2）、名刺データ化の作業グループ①〜⑧とは別の概念である（`04_admin_common_glossary.md` §2）。
- グループ専用の請求先が設定されている場合、請求の宛先は作成者本人と異なる（`user/05_group_edit_requirements.md` §3.3）。請求先として表示する情報をどちらにするかは §11 で確定する。
- グループ名の表示はアンケート詳細（SCR-A-005）§4.2、ユーザー詳細（SCR-A-003）§4.4 と同じ値を用いる。
- 一覧はページングと表示件数の選択に対応する（`01_admin_common_ui.md` §4.3）。
- 各列で昇順・降順の並び替えができる。
- 絞り込み結果の請求金額の合計（全ページ分）と件数を一覧の下に表示する。データ化中の請求の見込み額を含む。

### 4.3 検索・絞り込み

| 条件 | 種別 | 内容 |
| --- | --- | --- |
| アンケート | 検索 | アンケート ID またはタイトルの部分一致で絞り込む |
| ユーザー ID | 検索 | 完全一致または前方一致で対象を絞り込む |
| 会社名 | 検索 | 部分一致で絞り込む |
| グループ | 絞り込み | グループ単位で請求を絞り込む |
| 支払期日 | 絞り込み | 開始日〜終了日の期間指定で絞り込む。片側だけの指定もできる。支払期日が未確定の請求（データ化中）は期間指定時に対象へ含めない |

- 条件をまとめて初期状態へ戻す操作を用意する。
- 他画面から遷移した場合は、遷移元が指定した条件で絞り込んだ状態で開く（`01_admin_common_ui.md` §4.1.1）。受け取る条件は上表の 5 条件とする。

### 4.4 請求金額の算出と調整

- 請求金額は、名刺データ化とお礼メール送信の費用を合算した値を表示する（算出式は §11 の #3）。
- 名刺データ化の費用は、実際の件数とデータ化申込プランの単価から算出する。
- お礼メール送信の費用は、送信通数から無料枠を控除した通数へ単価を掛けて算出する。無料枠と単価は利用者側の定義（100 通まで無料、101 通目以降 1 円／通）に従う（`docs/リライト版仕様書/user/07_thank_you_email_settings_requirements.md`）。
- 内訳は、名刺データ化費用・お礼メール送信費用・クーポン割引・小計・請求金額の順に、品目・数量・単価・金額の列で表示する。品目名は利用者側の請求書と揃える（`16_admin_invoice.md` §4.4）。お礼メールは送信通数と無料枠の控除通数を併記し、費用が 0 円の場合も行を省略しない。
- 金額の調整はクーポン割引の事後適用（§4.6）で行い、調整の内容をクーポン割引率とクーポンメモへ記録する。割引はお礼メールを含む小計に対して掛ける。

### 4.5 締め支払いの規則（2026-08-17 追加）

支払条件は月末締め翌月払いとする。支払期日は締め月の翌月末を既定とする。

- 現行モック `03_admin/billing-management.html` の支払期日は請求日の 30 日後で作られており、この規則に従っていない。実データの並びを規則へ合わせるかは※要確定（§11 の #14）。

### 4.6 クーポン割引の事後適用

- 請求の確定後に、クーポンによる割引を適用する。
- 適用できる期間は当月内とする。
- 適用すると請求金額を再計算し、クーポン割引率とクーポンメモを更新する。
- 適用時は確認ダイアログを表示し、対象の請求と適用後の金額を明示する（`01_admin_common_ui.md` §7.1）。
- 適用済みの請求では、行の操作を適用中のクーポンコードの表示に切り替える。押下すると適用内容を確認するモーダルを開き、そこから適用を取り消せる。
- 適用の取り消しは監査ログの記録対象とする（`02_admin_common_audit_log.md` §3）。取り消し後は請求金額を適用前の値へ戻す。
- クーポンそのものの発行・編集は `17_admin_coupon.md` で行う。本画面は個別の請求へ適用する実行場所とする。

### 4.7 検討中の要件

| 要件 | 内容 |
| --- | --- |
| 請求書の出力 | 請求内容を請求書の形式で出力する。請求書管理（未採番）との責務分担は §11 で確定する |

## 5. 通知

本画面の操作を起点とする通知・メールの発火はない（`03_admin_common_notifications.md` §2）。

## 6. 権限とデータ範囲

| 権限レベル | 扱い |
| --- | --- |
| Lv1 | 本画面へアクセスできない。サイドバーに項目を表示しない |
| Lv2 | 本画面へアクセスできない。サイドバーに項目を表示しない |
| Lv3 | 全範囲の請求を表示・操作できる |
| Lv4 | 全範囲の請求を表示・操作できる |

- 本画面は金銭情報を扱うため、Lv2 以下はテナント分離により到達しない（`00_admin_common_permissions.md` §3）。
- 権限判定はサーバー側で行う（`00_admin_common_permissions.md` §9.1）。

## 7. 状態と挙動

### 7.1 初期表示

- 検索条件は未入力の状態で表示する。
- 一覧の既定の並び順は支払期日の昇順とし、期日が近い請求を先頭に表示する。
- 表示件数の既定は 50 件とする。

### 7.2 金額の算出

- 名刺データ化の費用は実際の件数とデータ化申込プランの単価から、お礼メール送信の費用は無料枠を控除した通数から算出し、合算する。単価は利用者側画面のプラン定義と一致させる（`04_admin_common_glossary.md` §4）。
- クーポンを事後適用した場合は、適用時点の金額に対して割引を反映する。
- 算出式と端数処理は §11 の #3 で確定する。

### 7.3 該当が 0 件の場合

- 一覧の位置に該当なしの旨を表示する。

## 8. 現行画面からの引き継ぎ

現行画面 `/admin/payment` は次を備える。

| 現行の機能 | 本書での扱い |
| --- | --- |
| 一覧表示 | §4.2。請求ステータス列は引き継がない |
| 検索 | §4.3。請求ステータスの絞り込みは引き継がず、支払期日の期間指定へ置き換える |
| 請求金額の直接編集 | 引き継がない。金額は算出値とし、調整はクーポンの事後適用（§4.6）へ一本化する |
| 請求ステータス・請求日・支払期日・入金確認日の変更フォーム | 引き継がない（2026-08-18）。入金の管理は画面の外の運用とし、請求日・支払期日は算出値の表示のみとする |
| アンケート情報・アカウント一覧・アンケート一覧への遷移 | §9 |

- 引き継がない判断はスプレッドシート「管理者画面_たたき台」B 列（金額補正）からの方針変更を含む。シートへの反映は別途行う。

月次の請求書管理は現行では別画面（`/admin/invoice`）として存在するが、一覧データがエラーで表示されない状態である（`16_admin_invoice.md` §8）。

参考: 現行モック `03_admin/billing-management.html` は本書の内容と同期している（クーポン事後適用時の上限到達／期限切れチェックと適用・取消の確認モーダル、支払期日の期間絞り込み、絞り込み結果の請求金額合計の表示）。

## 10. 画面確認観点

モックアップ上で次を確認する。

- [ ] 一覧に §4.2 の項目が表示される
- [ ] 金額と単価が 3 桁ごとのカンマ区切りで表示され、単位が「円」である
- [ ] 単価がデータ化申込プランごとの値になっている
- [ ] 割引率が整数の百分率で表示される
- [ ] ユーザー ID・会社名による検索が機能する
- [ ] 支払期日の期間指定で絞り込める
- [ ] 絞り込み結果の請求金額合計（全ページ分）が一覧の下に表示される
- [ ] 請求金額と単価が編集不可の表示である
- [ ] クーポンの事後適用時に確認ダイアログが表示され、対象の請求と適用後の金額が明示される
- [ ] 初期表示の並び順が支払期日の昇順である
- [ ] アンケート情報・アカウント情報・アンケート一覧へ遷移できる
- [ ] Lv2 以下でログインした場合、本画面の URL へ直接アクセスしても表示されない

- [ ] グループが設定されたアンケートの請求で、グループ名が表示され会社名が併記される
- [ ] グループで絞り込める

## 11. 画面外の確認事項

| # | 項目 | 内容 |
| --- | --- | --- |
| 1 | 請求書とアンケートの単位関係 | 決着済み（2026-08-04）。費用はアンケート単位で発生し、請求書はアカウントと発行月の組み合わせで束ねる。プレミアム利用料のみアカウント単位で請求書へ直接載せる。 |
| 2 | 請求書管理との 1 本化 | 請求管理と請求書管理を 1 画面に統合するか、別画面のまま運用するかを確定する。統合する場合、本書と `16_admin_invoice.md` を 1 本へ統合する。 |
| 3 | 請求金額の算出式 | 実際の件数、プラン単価、クーポン割引率から請求金額を算出する式と、端数処理の方法を確定する。消費税の扱いを含む。 |
| 4 | 事後適用の期間制限 | クーポンの事後適用を「当月内」とする際の当月の起点（請求日基準か会期終了基準か）を確定する。 |
| 5 | 入金情報変更の記録 | 決着済み（2026-08-18）。入金の管理を本画面から外したため、確認対象が消滅した。 |
| 6 | 期日超過の督促 | 決着済み（2026-08-18）。入金の状態を持たないため、督促の機能は設けない。 |
| 7 | データ化完了予定日の算出 | 一覧に表示するデータ化完了予定日を、営業日カレンダーの設定から算出するかを確定する。`04_admin_common_glossary.md` §4 の納期日時との関係を併せて決める。 |
| 8 | 請求行の識別単位 | 一覧の 1 行が何を指すかを確定する。アンケート単位であれば、アンケート ID とタイトルを表示項目へ追加する必要がある。現行の表示項目は会社名と氏名までで、対象アンケートを一覧上で特定できない。 |
| 9 | 請求レコードの生成契機 | 請求レコードがいつ生成されるかを確定する。「実際の件数」が確定するのは名刺データ化の完了後であり、会期中の請求行に件数と金額をどう表示するかを併せて決める。 |
| 10 | 入金情報の同時実行 | 決着済み（2026-08-18）。入金情報の変更機能を廃止したため対象外。 |
| 11 | お礼メールの送信通数の出所 | 請求へ載せる送信通数を、実際の送信結果と回答数のどちらから取るかを確定する。本書は 1 回答につき 1 通として扱う。 |
| 12 | グループ請求の宛先 | グループ専用の請求先が設定されている場合、請求書の宛先と本画面の「会社名・氏名」をグループ側とアカウント側のどちらにするかを確定する。`12_admin_user_detail.md` §11 の #11、`14_admin_survey_detail.md` §11 の #11 と併せて確定する。 |
| 13 | 入金確認の督促に使う期間 | 決着済み（2026-08-18）。ダッシュボードの入金指標を廃止したため対象外。 |
| 14 | モックの支払期日の並び | 現行モックの支払期日が請求日の 30 日後で作られており、§4.5 の締め支払いの規則に従っていない。レビュー用に実データを規則へ合わせるかを確定する。 |
