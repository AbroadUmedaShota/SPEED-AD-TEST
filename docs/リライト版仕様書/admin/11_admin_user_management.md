# ユーザー管理 要件定義書

| 項目 | 値 |
| --- | --- |
| 対象画面 | `/admin/user` |
| 画面 ID | SCR-A-002 |
| 正本区分 | 本書を正本とする |
| owner | product |

## 1. 文書目的

- 本書は、ユーザー管理（顧客側の利用者アカウントの横断管理）の要件を定義する。
- 全画面に共通する権限、UI 規則、監査ログ、通知、用語は共通編を参照する。本書は本画面に固有の要件を扱う。
- 利用者 1 名ごとの詳細確認と個別編集は本書の対象外とし、`12_admin_user_detail.md` で扱う。
- 運営側の作業者アカウント（オペレーター）の管理は `23_admin_operator_management.md` で扱う。

## 2. 画面概要

- 全顧客の利用者アカウントを横断で検索し、状態を確認する画面。
- 運営でしか行えない操作（アカウントの停止、招待、代行対応の起点）を集約する。
- アンケートと請求へのハブとして機能し、対象ユーザーの案件と金銭の状態へ移動できる。
- 一覧は確認と横断操作の場とし、個別のアカウント情報の編集はユーザー詳細（SCR-A-003）で行う。

### 2.1 一覧と詳細の責務分担

| 画面 | 担当する操作 |
| --- | --- |
| ユーザー管理（本画面） | 横断検索、状態の確認、アカウントの停止、招待、詳細・アンケート・請求への遷移 |
| ユーザー詳細（SCR-A-003） | 個別のアカウント情報の変更、プレミアム契約状態の変更、パスワードの代行操作、紐づく案件と請求のまとめ確認 |

一覧に編集機能を集中させると、対象を取り違えた状態での変更が起きる。編集の主戦場を詳細側に置く。

## 3. 想定利用者と対象範囲

### 3.1 想定利用者

- 運営全体を管理する Lv3・Lv4。顧客からの問い合わせ対応、契約状態の確認、アカウントの停止判断を行う。

### 3.2 対象範囲

- 利用者アカウントの一覧・検索
- アカウント情報の確認
- アカウントの停止
- 利用者の招待
- アンケート一覧・請求情報・ユーザー詳細への遷移

### 3.3 対象外

- 個別のアカウント情報の編集とパスワードの代行操作（`12_admin_user_detail.md`）
- アンケートの内容と状態の操作（`13_admin_survey_management.md`）
- 請求金額の確認（`15_admin_billing.md`）
- オペレーターアカウントの管理（`23_admin_operator_management.md`）

## 4. 画面要件

### 4.1 共通構成

- ヘッダー、サイドバー、パンくずを表示する（`01_admin_common_ui.md` §2）。
- 画面タイトルを表示する。
- 画面は上から、検索・絞り込み条件、ユーザー一覧の順に配置する。
- 一覧の上部に、利用者の招待の操作を配置する。

### 4.2 一覧表示

各利用者について次を表示する。

| 表示項目 | 内容 |
| --- | --- |
| ユーザー ID | 利用者を一意に識別する ID |
| 会社名 | 所属する会社 |
| 氏名 | 利用者の氏名 |
| メールアドレス | ログインおよび通知の宛先 |
| アカウント状態 | 利用者アカウントの状態（`04_admin_common_glossary.md` §6.1） |
| 登録日時 | アカウントを登録した日時 |

- 招待中のアカウントは、有効・停止のアカウントと同一の一覧に表示する。招待専用の領域を別に設けない。
- 本登録が完了していないアカウントは、一覧上で識別できるように表示する。現行サービスの新規登録は仮登録から本登録へ進む 2 段階のフローであり、仮登録の段階にあるアカウントを本登録未了として扱う。
- 一覧はページングと表示件数の選択に対応する（`01_admin_common_ui.md` §4.3）。
- 各列で昇順・降順の並び替えができる。

### 4.3 検索・絞り込み

| 条件 | 種別 | 内容 |
| --- | --- | --- |
| ユーザー ID | 検索 | 完全一致または前方一致で対象を絞り込む |
| 会社名 | 検索 | 部分一致で絞り込む |
| 氏名 | 検索 | 部分一致で絞り込む |
| メールアドレス | 検索 | 部分一致で絞り込む |
| アカウント状態 | 絞り込み | 利用者アカウントの状態から選択する（`04_admin_common_glossary.md` §6.1）。初期値は「すべて」 |

条件をまとめて初期状態へ戻す操作を用意する。

他画面から遷移した場合は、遷移元が指定した条件で絞り込んだ状態で開く（`01_admin_common_ui.md` §4.1.1）。受け取る条件は上表の 5 条件とする。

### 4.4 アカウント情報の確認と編集

- 一覧から対象を選択するとユーザー詳細（SCR-A-003）へ遷移する。行のどこを押下しても遷移し、行内の操作は行の押下と分離する（`01_admin_common_ui.md` §4.5）。
- 一覧上で行える編集は、アカウントの停止（§4.5）に限る。その他の項目の変更はユーザー詳細で行う。

### 4.5 アカウントの停止

- 一覧から対象のアカウントを停止できる。
- 停止する際は確認ダイアログを表示し、対象のユーザー ID と会社名を明示する。
- 停止したアカウントはログインできない。
- 停止から有効へ戻すことができる。
- 停止操作は監査ログの記録対象とする（`02_admin_common_audit_log.md` §3）。

### 4.6 利用者の招待

- メールアドレスを指定して利用者を招待する。仮アカウントを作成し、状態を「招待中」とする。
- 招待の方式は `00_admin_common_permissions.md` §7.2 に従う。招待リンクの有効期限は発行から 72 時間とする。
- 招待中のアカウントに対して、招待メールの再送とキャンセルを実行できる。再送時は新しいリンクを発行し、有効期限を再度 72 時間とする。
- 招待の操作は §4.1 のとおり一覧の上部に配置し、招待中のアカウントは §4.2 の一覧に混在して表示する。
- 招待中の行はユーザー詳細を持たないため、行の押下による遷移を行わない。行の操作は再送と取り消しのリンク、および招待リンクの有効期限の表示とする（`01_admin_common_ui.md` §4.5）。
- 招待の実行・再送・キャンセルは監査ログの記録対象とする（`02_admin_common_audit_log.md` §3）。
- 招待で作成したアカウントの初期の権限と会社の紐付け方法は §11 で確定する。

## 5. 通知

本画面の操作を起点として次の通知が発火する（`03_admin_common_notifications.md` §2）。

| 契機 | 通知 | 宛先 |
| --- | --- | --- |
| 招待を実行したとき | 利用者招待メール | 招待先のメールアドレス |
| 招待を再送したとき | 利用者招待メール（再送） | 招待先のメールアドレス |

## 6. 権限とデータ範囲

| 権限レベル | 扱い |
| --- | --- |
| Lv1 | 本画面へアクセスできない。サイドバーに項目を表示しない |
| Lv2 | 本画面へアクセスできない。サイドバーに項目を表示しない |
| Lv3 | 全範囲の利用者アカウントを表示・操作できる |
| Lv4 | 全範囲の利用者アカウントを表示・操作できる |

- 本画面は顧客情報を扱うため、Lv2 以下はテナント分離により到達しない（`00_admin_common_permissions.md` §3）。
- 権限判定はサーバー側で行う（`00_admin_common_permissions.md` §9.1）。

## 7. 状態と挙動

### 7.1 初期表示

- 検索条件は未入力、アカウント状態の絞り込みは「すべて」の状態で表示する。
- 一覧の既定の並び順は登録日時の降順とし、新しく登録されたアカウントを先頭に表示する。
- 表示件数の既定は 50 件とする。

### 7.2 該当が 0 件の場合

- 一覧の位置に該当なしの旨を表示する。

### 7.3 詳細からの復帰

- ユーザー詳細から戻った場合、直前の検索条件・絞り込み条件・ページ位置を保持した状態で一覧を再表示する。
- 詳細画面で変更した内容は、再表示した一覧に反映する。

### 7.4 操作の記録

次の操作は監査ログに記録する（`02_admin_common_audit_log.md` §3）。

- アカウントの停止・停止解除
- 招待の実行・再送・キャンセル

## 8. 現行画面からの引き継ぎ

現行画面 `/admin/user` は次を備える。本画面はこれらの機能を引き継ぐ最低線とする。

現行画面のナビゲーションは本画面を「ユーザー(利用者)管理」と表記するが、本書は括弧書きを外して「ユーザー管理」とする（`01_admin_common_ui.md` §3）。

| 現行の機能 | 本書での扱い |
| --- | --- |
| 一覧表示 | §4.2 |
| 検索 | §4.3 |
| アカウント情報の編集 | §4.4。編集はユーザー詳細（SCR-A-003）へ移す |
| 停止チェック | §4.6 |
| アンケート・請求への遷移 | §9 |

参考: 現行モック `03_admin/user-management.html` は、氏名・メール・ID の検索と状態・プランによる絞り込みを持つ（部署名・役職名の絞り込みは持たない・2026-08-12 時点）。モックは仕様上の正解とは扱わない。

## 10. 画面確認観点

モックアップ上で次を確認する。

- [ ] ユーザー ID・会社名・氏名・メールアドレスによる検索が機能する
- [ ] アカウント状態による絞り込みが機能する
- [ ] 招待中のアカウントが有効・停止のアカウントと同じ一覧に表示される
- [ ] 本登録未了のアカウントが一覧上で識別できる
- [ ] 一覧から対象を選択するとユーザー詳細へ遷移する
- [ ] アカウントの停止時に確認ダイアログが表示され、対象のユーザー ID と会社名が明示される
- [ ] 停止したアカウントが一覧上で停止状態として表示され、停止から有効へ戻せる
- [ ] 招待を実行すると一覧に状態「招待中」のアカウントが表示される
- [ ] 招待中のアカウントに対して再送とキャンセルの操作が表示される
- [ ] Lv2 以下でログインした場合、本画面の URL へ直接アクセスしても表示されない

## 11. 画面外の確認事項

| # | 項目 | 内容 |
| --- | --- | --- |
| 1 | 削除の方式 | 利用者アカウントの削除をどう扱うかを確定する。停止で運用するか、削除を設けるか、削除する場合に紐づくアンケート・回答・請求をどうするかを決める。 |
| 2 | アカウント状態の値集合 | 有効・停止・招待中・本登録未了の 4 値で運用に足りるかを確定する。解約に相当する状態を別に持つかを含めて決める。オペレーター側の「無効」との表記統一、および「招待中」と「本登録未了」を単一の状態値とするかは `04_admin_common_glossary.md` §8 で確定する。 |
| 3 | 本登録未了の判定 | 仮登録から本登録へ進む 2 段階フローのうち、どの状態を本登録未了とみなすかを確定する。仮登録の有効期限も併せて決める。 |
| 4 | 招待アカウントの初期設定 | §4.6 の招待で作成したアカウントの初期の権限と、会社の紐付け方法を確定する。既存の会社へ追加するか、招待時に会社を新規作成するかを含めて決める。 |
| 5 | 会社とユーザーの関係 | 1 つの会社に複数の利用者が所属する場合の一覧表示（会社単位でまとめるか、利用者単位で並べるか）を確定する。 |
| 6 | 停止時の影響範囲 | アカウントを停止した際に、そのユーザーが作成した会期中のアンケートと回答受付をどう扱うかを確定する。あわせて、停止・削除した際に名刺データ化キュー（入力中・照合中の名刺）へどう波及するかを決める。作業中の名刺を出題対象から外すか、作業を完了させてから停止を反映するかで、作業者側の挙動が変わる。 |
