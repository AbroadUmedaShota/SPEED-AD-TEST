## 1. 文書目的

- 本書は、名刺データの入力を行う作業画面の要件を定義する。
- 全画面に共通する権限、UI 規則、監査ログ、通知、用語は共通編を参照する。本書は本画面に固有の要件を扱う。
- 作業の入口となる一覧と進捗管理は本書の対象外とし、`19_admin_data_input_list.md` で扱う。
- 入力結果を突き合わせて確定する照合作業は `22_admin_matching_form.md` で扱う。

## 2. 画面概要

- 名刺画像を見ながら項目を入力し、確定して次の名刺へ進む作業画面。
- 1 件あたりの操作回数と待ち時間が処理量に直結するため、キーボードのみで一連の操作を完結できる構成とする。
- 出題順は納期の優先順位に従い、オペレーターは対象を選ばない。
- 判断できない名刺はスキップし、後続の処理へ引き渡す。

## 3. 想定利用者と対象範囲

### 3.1 想定利用者

- 入力作業を行う Lv1（Operator）。本画面の主たる利用者であり、連続して入力を行う。
- 作業を管理する Lv2（OperatorAdmin）。自グループの入力作業を確認・代行する。

### 3.2 対象範囲

- 名刺画像の表示と画像操作
- 項目の入力と確定
- スキップ
- 出題順の制御

### 3.3 対象外

- 入力対象の進捗管理と作業開始の導線（`19_admin_data_input_list.md`）
- 入力結果の突き合わせと最終確定（`22_admin_matching_form.md`）
- 例外名刺の処理（エスカレーション画面 SCR-A-016 は検討凍結中）
- 名刺画像の取得と保管（回答者側の送信処理）

## 4. 画面要件

### 4.1 共通構成

- 誤操作を防ぐためサイドバーは表示しない（`01_admin_common_ui.md` §2）。主要領域は縦スクロールなしで 1 画面に収める。離脱の導線は「一覧へ戻る」ボタンとする。
- 画面は左右 2 領域で構成する。一方に名刺画像、他方に入力フォームを配置する。
- 本画面で扱う入力項目は、遷移元（`19_admin_data_input_list.md` §4.4）で選択した作業グループの項目に限る。ただし全グループ入力（§4.8）では①〜⑧のすべてを扱う。
- 画面上部に、対象が属するアンケートのアンケート ID、納期区分、作業中の作業グループ、対象言語、および残りの作業可能件数を表示する。オペレーターへ提示するアンケート情報は ID までとする。
- 対象言語は遷移元（`19_admin_data_input_list.md` §4.2）で選択した値を表示する。「自動」のままであればその旨を示す。言語非依存の作業グループ（§4.4）では対象言語で絞られないため「全言語」と示す。
- 残りの作業可能件数は、作業中の作業グループを対象とした件数とする。

### 4.2 名刺画像の表示と操作

- 名刺画像を入力フォームと同時に視認できる大きさで表示する。
- 画像はマウスオーバーでカーソル位置を起点に拡大表示し、クリックでその位置・倍率のまま固定できる（再クリックで解除）。拡大率の調整と 90 度単位の回転の操作を提供する。
- 拡大率は 1.0 倍から 4.0 倍の範囲を 0.5 刻みで調整する。初期値は 2.0 倍とする。現在の拡大率は画像領域の見出しに表示する。
- 表裏の画像を同時に表示する。
- 裏面の画像が無い名刺では、裏面の枠を残したまま「裏面なし」と明示する。枠ごと消すと、裏面が無いのか画像の登録漏れなのかを区別できないため。
- 画像操作はキーボードからも実行できるようにする。
- 画像操作・確定・スキップの各操作要素には、ショートカットの説明をツールチップで付す。

### 4.3 出題順

対象の名刺は次の順序で出題する。オペレーターが対象を指定して選ぶ操作は設けない。

1. 納期区分の優先順位。優先度の高い順に オンデマンド、超特急、特急、通常、お試し（お試しの位置は※要確定・`04_admin_common_glossary.md` §8 の #5）。
2. 同一の納期区分内では、回答の受付順（古い順）。

### 4.4 項目の入力

- 名刺データ化の対象項目は作業グループ①〜⑧に分かれる。内訳を次表のとおりとする（※要確定・§11 の #1）。本画面が一度に扱うのは、このうち作業中の作業グループの項目である（§4.1）。
- 入力欄はキーボードのみで移動でき、順序は画面上の配置と一致させる。
- 名刺から読み取れない箇所には「〓」を入力する。空欄のまま確定しない。「〓」は文字単位で用い、読み取れない文字の位置に入れる（例: 姓の 2 文字目だけが潰れている場合は「山〓」）。項目全体が読み取れない場合は、その項目を「〓」だけにする。
- 入力補助として各項目に「〓」の入力チップを置く。チップはカーソル位置へ「〓」を挿入するものとし、入力済みの値を消さない。空欄で押した場合は結果として項目全体が「〓」になる。
- 入力内容は確定操作で保存し、次の名刺を表示する。確定はキーボード操作で実行できる。
- 作業グループ④では、郵便番号の入力に応じて住所 1 の候補を表示する。候補は押下したときだけ入力欄へ反映し、自動では上書きしない。番地・建物名は名刺を見て追記する前提とし、その旨を候補の横に添える。参照する住所データの調達方法は §11 の #12 で確定する。

| 作業グループ | 入力項目 | 言語依存 |
| --- | --- | --- |
| ① | メールアドレス | 非依存 |
| ② | 姓、名 | 依存 |
| ③ | 会社名、部署名、役職名 | 依存 |
| ④ | 郵便番号、住所 1、住所 2 | 依存 |
| ⑤ | 電話番号 1、電話番号 2、携帯番号、FAX 番号 | 非依存 |
| ⑥ | URL | 非依存 |
| ⑦ | その他メモ | 依存 |
| ⑧ | フリー入力 | 依存 |

- 言語依存の欄は、入力値が名刺の言語に左右されるかを示す。①・⑤・⑥ は入力値が数字と ASCII 文字に限られるため、名刺の言語を読めなくても入力できる。
- 言語非依存の作業グループは、オペレーターの対応可能言語に関わらず全オペレーターへ出題する。データ入力対象一覧（SCR-A-009）の対象言語でも絞り込まない（`19_admin_data_input_list.md` §4.3）。
- ④ は郵便番号のみを取り出せば言語非依存だが、住所 1・住所 2 が現地語表記であり、かつ郵便番号から住所 1 の候補を出す連動があるため、グループとして言語依存に含める。作業グループに 1 つでも言語依存の項目があれば、そのグループは言語依存とする。
- 言語依存の区分は DB のマスタで管理し、本画面およびデータ入力対象一覧からは変更しない。言語マスタと同じ扱いとする（`23_admin_operator_management.md` §4.10）。

- 入力欄の表示順は上表の並び順とする。
- 各項目はテキスト入力とする。その他メモとフリー入力は複数行の入力とする。必須の項目は設けず、読み取れない箇所には「〓」を入力する（§4.4）。
- 入力欄のプレースホルダには入力例を表示する（メールアドレスなら `xxx@example.co.jp`、郵便番号なら `100-0001` など）。
- 各項目の最大文字数は確定前とする（※要確定・§11 の #1）。
- 入力項目のマスタ化は本番化工程で扱う。モックアップでは本表を正とする。

- 入力欄で `Enter` を押下すると次の項目へ移動する。最終の入力欄では確定の操作へ移動する。`Ctrl + Enter` で確定して次の名刺へ進む（キー割当の確定は §11 の #8）。
- 画面上部にショートカット一覧を開く導線を置く。一覧は `?` からも開閉できる。

参考: 現行画面 `/admin/data_input_screen` は `Ctrl + Enter` で確定する。

参考: 現行モック `03_admin/data-entry/form.html` は本書の内容と同期している（表裏同時表示・ホバー拡大とクリック固定・欄別の定型チップ・Enter による欄移動）。

### 4.5 スキップ

- 判断できない名刺はスキップし、次の名刺へ進む。
- スキップの実行時は理由の選択を求める。選択肢は「名刺ではない」「対応言語外」「その他」の 3 つとする。「その他」を選んだ場合は理由の入力を必須とし、未入力の間は実行を受け付けない。
- 「対応言語外」は言語非依存の作業グループ（§4.4）では選択肢に出さない。入力値が名刺の言語に左右されないため、読めない言語でも入力できるからである。言語依存の作業グループでは、対応可能言語の外を自分で選べる（`19_admin_data_input_list.md` §4.2）ため、選んだ言語を読めなかった場合の戻し先として残す。
- 現行画面が持つ「エスカレーション」は選択肢から外す（2026-08-08 の指示）。エスカレーション画面（SCR-A-016）が検討凍結中で引き渡し先が無く、選んでも他の理由と同じ扱いにしかならないため。凍結が解除された場合の扱いは §11 の #3 で確定する。
- スキップの操作を開くたびに、理由の選択と入力を既定の状態へ戻す。前の名刺で選んだ理由が次の名刺へ持ち越されないようにする。
- スキップ理由の記録先（監査ログの記録対象とするか）は確定前とする（※要確定・§11 の #11）。
- スキップした名刺は全体キューへ戻り、他のオペレーターへの出題対象となる。この動作は同一アンケート内に閉じない（`19_admin_data_input_list.md` §7.2）。
- 同一の名刺が 3 回スキップされた場合、出題対象から除外し、データ入力対象一覧・照合結果一覧上で識別表示する。エスカレーション画面（SCR-A-016）の検討が凍結中であるための暫定の挙動とする。凍結解除後の引き渡し先は §11 で確定する。
- 3 回スキップされて出題対象から外れた名刺は、読み取れる範囲を入力し、読み取れない箇所を「〓」として確定する扱いを基本とする。エスカレーション画面の凍結中における当面の受け皿とする（§11 の #3）。
- 名刺以外の画像、言語判定の誤りによる出題も同じ扱いとする。

### 4.6 作業ロック

- 出題した名刺はロックし、他のオペレーターへ同時に出題しない。
- 操作がないまま 3 分が経過した場合、ロックを自動解除して全体キューへ戻す。
- ロックの解除後は名刺画像を伏せ、解除された旨と再取得の導線を表示する。解除された名刺は他のオペレーターへ出題し直されるため、画像を見続けられる状態にしない。入力内容は保持し、対象を再取得すればそのまま確定できる。
- ロックの解除中は確定・スキップを受け付けず、対象を再取得する必要がある旨を示す。
- 挙動と解除時間は名刺情報照合（`22_admin_matching_form.md` §4.6）と揃える。

### 4.7 追加要件（あったほうが良い）

| 要件 | 内容 |
| --- | --- |
| OCR 結果・他オペレーター入力の表示 | 同一名刺に対する OCR 結果と他オペレーターの入力を表示し、押下で入力欄へ複写する |
| QR コード・バーコードの読み取り入力 | 名刺上のコードを読み取って項目へ反映する |
| 定型チップによる入力 | 頻出する値を各入力欄の直下にチップとして配置し、押下で入力する。同じ括り（法人格・部署・役職など）の語が既にある場合は置換して二重入力を防ぎ、同語の再押下で解除する |
| エスカレーション登録 | 判断できない名刺を例外として登録する（エスカレーション画面が検討凍結中のため §11 で確定） |

### 4.8 全グループ入力

- 1 枚の名刺の作業グループ①〜⑧をまとめて入力する形態を設ける。Lv4 にのみ提供する（§6）。
- 画面構成は通常の入力と同じとし、入力フォームに作業グループの見出しを挟んで①〜⑧の全項目を順に並べる。
- 出題順・スキップ・作業ロック・ショートカットは通常の入力と同じ扱いとする。
- 画面区分（独立した画面 ID を割り当てるか、入力画面のモードとするか）と、確定内容を「入力 1〜3」のどれとして扱うかは `19_admin_data_input_list.md` §11 の #7 で確定する。

## 5. 通知

本画面の操作を起点とする通知・メールの発火はない（`03_admin_common_notifications.md` §2）。

## 6. 権限とデータ範囲

| 権限レベル | 扱い |
| --- | --- |
| Lv1 | 自グループの名刺のみを入力できる |
| Lv2 | 自グループの名刺のみを入力できる |
| Lv3 | 全グループの名刺を入力できる |
| Lv4 | 全グループの名刺を入力できる |

- 権限判定とデータ範囲の絞り込みはサーバー側で行う（`00_admin_common_permissions.md` §9.1）。
- 管理者（Lv3・Lv4）が入力を代行する範囲は §11 で確定する。
- 全グループ入力（§4.8）は Lv4 にのみ提供する。Lv3 以下は URL を直接指定しても入力できない。

## 7. 状態と挙動

### 7.1 初期表示

- データ入力対象一覧から遷移した時点で、§4.3 の順序に従って最初の対象を表示する。
- 入力欄は空の状態で表示し、先頭の入力欄にフォーカスを置く。

### 7.2 確定後の遷移

- 確定すると入力内容を保存し、次の対象を同一画面に表示する。画面遷移は発生させない。
- 確定・スキップの直後 6 秒間、直前の操作を取り消す導線を画面上部に表示する。取り消すと前の名刺と入力内容を復元する。誤って確定・スキップした直後の復帰を目的とする。
- 対象が残っていない場合は、その旨を表示しデータ入力対象一覧へ戻る導線を提供する。入力欄と画像操作は操作できない状態とする。

### 7.3 複数オペレーターによる入力

- 同一の名刺に対して複数のオペレーターが入力する。入力結果は個別に保持し、後続の照合で突き合わせる。
- 入力結果が所定の条件を満たした名刺は確定済みとなり、以降は出題対象から外れる。確定条件の定義は §11 で確定する。

### 7.4 入力の中断

- 入力途中で画面を離れる場合、入力内容がある間は確認ダイアログを表示する（`01_admin_common_ui.md` §8）。
- 確定していない入力内容は保存しない。

### 7.5 応答時間

- 確定操作から次の名刺が表示されるまでの時間は 1 秒以内を目標とする（`05_admin_nonfunctional.md` §2）。

## 8. 現行画面からの引き継ぎ

現行画面 `/admin/data_input_screen` は次を備える。本画面はこれらの機能を引き継ぐ最低線とする。

| 現行の機能 | 本書での扱い |
| --- | --- |
| 名刺画像を見ながらの入力 | §4.2、§4.4 |
| スキップ理由の選択（名刺ではない／対応言語外／エスカレーション／その他） | §4.5。4 つをそのまま引き継ぎ、選択肢の追加・削除は行わない。エスカレーションを選んだ名刺の引き渡し先は §11 の #3 で確定する |
| `Ctrl + Enter` による確定 | §4.4 |
| スキップ | §4.5 |

現行画面には画像の拡大・縮小・回転の操作が確認できていない。§4.2 は新規に追加する要件として扱う。

## 10. 画面確認観点

モックアップ上で次を確認する。

- [ ] 名刺画像と入力フォームが同一画面に同時に表示される
- [ ] サイドバーが表示されず、主要領域が縦スクロールなしで 1 画面に収まる
- [ ] 画面上部に対象のアンケート ID、納期区分、作業中の作業グループ、対象言語、残りの作業可能件数が表示される
- [ ] 遷移元で選んだ対象言語が表示され、言語非依存の作業グループでは「全言語」と表示される
- [ ] 入力欄が作業中の作業グループの項目だけで構成される
- [ ] 入力欄のプレースホルダに入力例が表示される
- [ ] 表裏の画像が同時に表示される
- [ ] 裏面の画像が無い名刺で「裏面なし」と明示される
- [ ] 画像のホバー拡大・クリックによる固定と解除・回転が実行できる
- [ ] 入力欄の移動と確定がキーボードのみで完結する
- [ ] 入力欄の移動順が画面上の配置と一致する
- [ ] 確定後、画面遷移を伴わずに次の名刺が表示される
- [ ] 出題順が納期区分（オンデマンド、超特急、特急、通常、お試し）の優先順位に従う
- [ ] 同一納期区分内の出題順が回答の受付順である
- [ ] スキップ操作で理由の選択を求められ、「その他」では理由の入力が必須になる
- [ ] スキップの理由に「エスカレーション」が無い
- [ ] 言語非依存の作業グループ（①・⑤・⑥）ではスキップの理由に「対応言語外」が出ない
- [ ] スキップ操作で次の名刺へ進む
- [ ] 確定・スキップの直後に、直前の操作を取り消す導線が一定時間表示される
- [ ] 読み取れない箇所に「〓」を入力して確定できる
- [ ] 「〓」の入力チップがカーソル位置へ挿入され、入力済みの値が消えない
- [ ] ショートカット一覧を画面上の導線と `?` の両方から開ける
- [ ] 対象が残っていない場合、その旨とデータ入力対象一覧へ戻る導線が表示される
- [ ] 入力途中で画面を離れようとした場合に確認ダイアログが表示される
- [ ] 作業グループ④で郵便番号を入力すると住所 1 の候補が表示され、押下したときだけ入力される
- [ ] ロックが解除されると名刺画像が伏せられ、再取得の導線が表示される
- [ ] ロックの解除中は確定・スキップを実行できない
- [ ] Lv4 で全グループ入力を開くと、①〜⑧の全項目が作業グループの見出し付きで並ぶ
- [ ] Lv3 以下で全グループ入力の URL へ直接アクセスしても入力できない
- [ ] Lv1・Lv2 でログインした場合、他グループの名刺が出題されない

## 11. 画面外の確認事項

| # | 項目 | 内容 |
| --- | --- | --- |
| 1 | 入力項目の詳細とマスタ化 | §4.4 の項目表を正式な入力項目として確定し、各項目の最大文字数と入力形式（半角・全角の指定、区切り記号の扱い）を定める。項目構成をマスタで管理する方式（保持先と変更手順）を併せて決める。完成データの出力項目と一致させる。 |
| 2 | 確定条件の定義 | 同一名刺の入力が何をもって確定するかを確定する。OCR 結果と入力の一致、複数オペレーター入力の一致のいずれを条件とするかで、必要な入力回数が変わる。照合の一致・不一致判定（`22_admin_matching_form.md` §11 の #2）、照合結果一覧の完了件数（`21_admin_matching_list.md` §11 の #5）、オペレーター実績確認の正答率の分母（`24_admin_achievements.md` §11 の #1・#2）と併せて、本項を含む 4 点を同一の定義で確定する。 |
| 3 | イレギュラーの引き渡し先 | 3 回スキップされた名刺、名刺以外の画像、言語判定の誤りによる出題、およびスキップ理由に「エスカレーション」が選ばれた名刺の引き渡し先を確定する。エスカレーション画面が凍結中のため、当面の受け皿を決める必要がある。 |
| 4 | エスカレーション登録の存続 | §4.7 のエスカレーション登録を、凍結解除後に提供するかを確定する。スキップ理由からは 2026-08-08 に「エスカレーション」を外している（§4.5）。 |
| 5 | 管理者による代行入力 | Lv3・Lv4 が入力を代行できる範囲を確定する。代行入力を実績集計に含めるかも併せて決める。 |
| 6 | 「〓」の後続処理 | 文字単位で混在する「〓」を含む入力が、照合と完成データでどう扱われるかを確定する（`04_admin_common_glossary.md` §8 の #6 と連動）。 |
| 7 | 出題の排他制御 | 同一名刺を同時に何名まで出題対象とするかを確定する。制限しないと同一名刺への入力が過剰に集まる。§4.6 の作業ロック（無操作 3 分で解除）はモックの暫定値であり、正式な解除時間は `22_admin_matching_form.md` §11 の #4 と同時に確定する。 |
| 8 | キーボード操作の割当 | 確定、スキップ、画像操作、入力欄移動に割り当てるキーを確定する。現行の `Ctrl + Enter` を維持するかを含む。現行モックの暫定割当は Enter=次の欄（最終欄では確定ボタンへ）、Ctrl+Enter=確定して次へ（スキップ確認中はスキップを実行）、Esc=スキップ（理由を選択）、F2=フォーカス中の欄へ OCR 候補を複写（※暫定割当）、+/−=拡大率（入力中は Alt 併用）、R=回転（入力中は Alt+R）、?=ショートカット一覧。Ctrl+Z（複写・チップ入力の取り消し）と Ctrl+Shift+Z（直前の確定・スキップの取り消し）は 2026-08-08 に廃止した。直前の操作の取り消しは画面上部の導線から行う。 |
| 9 | 多言語名刺の扱い | 言語ごとに入力項目や入力形式が変わるかを確定する。言語判定の実装内容は開発側へ開示を要求中である。 |
| 10 | 存在しない項目の入力規則 | 名刺にそもそも存在しない項目（FAX 番号が無い名刺など）をどう入力するかを確定する。読み取れない項目に用いる「〓」と区別するか、空欄可とするかを決める。照合側は空欄のまま確定して「(記載なし)」として扱う方式をモックに入れている（`22_admin_matching_form.md` §4.5・§11 の #11）。入力側と照合側で同じ規則にし、完成データの CSV 出力での表記を併せて決める（`04_admin_common_glossary.md` §8 の #6 と連動）。 |
| 11 | スキップ理由の記録先 | §4.5 で選択・入力したスキップ理由をどこに残すかを確定する。監査ログの記録対象とするか（`02_admin_common_audit_log.md` §3）、名刺ごとの作業履歴として持つかを決める。3 回スキップの判定と、イレギュラーの引き渡し（#3）で理由を参照するかを併せて決める。 |
| 12 | 住所データの調達 | §4.4 の郵便番号からの住所候補が参照する住所データをどう用意するかを確定する。日本郵便の公開データを取り込むか、外部 API を利用するかで、更新の運用と費用が変わる。モックは代表的な数件のみを持つ暫定辞書である。 |
