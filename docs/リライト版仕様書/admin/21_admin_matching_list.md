## 1. 文書目的

- 本書は、照合結果一覧の要件を定義する。
- 全画面に共通する権限、UI 規則、監査ログ、通知、用語は共通編を参照する。本書は本画面に固有の要件を扱う。
- 1 件ごとの照合作業（項目の見比べ、修正入力、確定）は本書の対象外とし、`22_admin_matching_form.md` で扱う。

## 2. 画面概要

- 照合の進み具合と納期をアンケート単位で把握するための画面。
- 照合作業を開始する入口であり、照合完了後の完成データを確認・取得する出口でもある。
- 対象アンケートを一覧で示し、各アンケートの総件数・未入力・一致・不一致と納期日時を数値で表示する。
- 表示範囲はログイン中アカウントのデータ範囲に従う（§6）。

## 3. 想定利用者と対象範囲

### 3.1 想定利用者

- 照合作業を行う Lv2（OperatorAdmin）。自グループのアンケートを対象に、照合の進捗確認と作業開始を行う。
- 運営全体を管理する Lv3・Lv4。全グループのアンケートを対象に、納期の遅れと完成データの状態を確認する。

### 3.2 対象範囲

- 照合対象アンケートの一覧表示と集計サマリ
- 検索、絞り込み、並び替え
- 照合作業の開始（名刺情報照合への遷移）
- 完成データおよび全レコードのダウンロード

### 3.3 対象外

- 名刺 1 件ごとの照合操作（`22_admin_matching_form.md`）
- 名刺データの入力作業と入力の進捗管理（`19_admin_data_input_list.md`、`20_admin_data_input_form.md`）
- 例外名刺の処理（エスカレーション画面 SCR-A-016 は検討凍結中）
- 納期の算出根拠となる営業日設定（`18_admin_calendar.md`）

## 4. 画面要件

### 4.1 共通構成

- ヘッダー、サイドバー、パンくずを表示する（`01_admin_common_ui.md` §2）。
- 画面タイトルを表示する。
- 画面は上から、集計サマリ、検索・絞り込み条件、アンケート一覧の順に配置する。

### 4.2 集計サマリ

画面上部に、現在の照合状況を示す数値を表示する。

| 項目 | 内容 |
| --- | --- |
| 進行中の作業対象アンケート数 | 照合作業が進行中のアンケートの件数。ダッシュボード（SCR-A-001）§4.2 の「照合待ちのアンケート数」と同じ数を指す |

- 数値カードとして表示する（`01_admin_common_ui.md` §5）。
- 集計対象はログイン中アカウントのデータ範囲に限定する。
- 集計の最終更新日時を併せて表示する。

現行画面はこれに加えて、エスカレーションありの要確認名刺数を表示している。エスカレーションの扱いは検討凍結中のため、本項目の存続は §11 で確定する。

### 4.3 検索・絞り込み・並び替え

| 条件 | 種別 | 内容 |
| --- | --- | --- |
| アンケート ID | 検索 | 完全一致または前方一致で対象アンケートを絞り込む |
| ユーザー ID | 検索 | アンケートの所有者であるユーザー ID で絞り込む |
| 会社名 | 検索 | 部分一致で絞り込む。Lv3 以上にのみ表示する（§6） |
| 作業ステータス | 絞り込み | 作業ステータスの値から選択する。初期値は「すべて」 |
| 納期区分 | 絞り込み | データ化申込プランの納期区分から選択する。初期値は「すべて」 |

- 検索欄と絞り込み欄は一覧の上部にまとめて配置する。条件をまとめて初期状態へ戻す操作を用意する。
- 並び替えの対象は上記の条件と納期日時とする。列見出しの押下で昇順・降順を切り替える。納期の把握が本画面の目的であるため、納期日時を並び替えの対象に含める。
- 作業ステータスの値集合は画面間で一致していない。正とする値集合は `04_admin_common_glossary.md` §6.2 で確定する。

### 4.4 アンケート一覧

各アンケートについて次を表示する。

| 表示項目 | 内容 |
| --- | --- |
| アンケート ID | アンケートを一意に識別する ID |
| タイトル | アンケートのタイトル |
| 会社名 | アンケートの所有者が所属する会社名。Lv3 以上にのみ表示する（§6） |
| 納期区分 | データ化申込プランの納期区分（お試し・通常・特急・超特急・オンデマンド） |
| 会期 | 回答受付期間の開始日と終了日 |
| 総件数 | 照合対象の名刺の総件数 |
| 未入力 | 入力作業が完了していない件数 |
| 一致 | 突き合わせの結果が一致した件数 |
| 不一致 | 突き合わせの結果が一致しなかった件数 |
| 進捗 | 「完了件数 / 総件数」と百分率。完了件数の定義は §11 の #5 で確定する |
| 納期日時 | 完成データの納品期限（日付と時刻） |

- 件数は 3 桁ごとのカンマ区切りで表示する。納期日時は `YYYY/MM/DD HH:MM` で表示する（`01_admin_common_ui.md` §9）。
- 進捗の百分率は整数で表示する（`01_admin_common_ui.md` §5）。
- 納期日時を過ぎているアンケートは、一覧上で他と区別して表示する。
- 一覧はページングと表示件数の選択に対応する（`01_admin_common_ui.md` §4.3）。
- 幅が足りない場合は横スクロールにせず、次の順で列を隠す（`05_admin_nonfunctional.md` §6.2）。1366px まで横スクロールを出さない。
  1. 総件数・一致・不一致。未入力と進捗が残るため進み具合は追える
  2. 会期。納期日時が残るため締め切りの判断はできる
- 表示形式（表形式・カード形式）は §11 で確定する。表示項目は形式によらず本節のとおりとする。

### 4.5 一覧からの操作

| 操作 | 内容 |
| --- | --- |
| 照合を開始する | 対象アンケートの名刺情報照合（SCR-A-013）へ遷移し、照合作業を開始する |
| 完成データをダウンロードする | 納品対象の完成データをファイルとして取得する。照合が完了したデータの内容の確認も、このファイルの取得で行う |
| 全レコードをダウンロードする | 照合の途中経過を含む対象アンケートの全データをファイルとして取得する |
| 回答データをダウンロードする | 名刺のデータ化結果ではなく、アンケートの設問回答をファイルとして取得する |

- ダウンロードの導線は 1 つにまとめ、押下したモーダルの中で完成データ CSV・全レコード CSV・回答データ CSV・名刺画像（ZIP）を選択する。アンケート管理（`13_admin_survey_management.md` §4.7）と同じ構成とする。
- 回答データ CSV は名刺のデータ化結果を含まない。照合の状況を確認する場面で設問回答も併せて必要になるため、同じモーダルから取得できるようにする。名刺のデータ化結果との取り違えを避けるため、選択肢の説明に何が入るかを明記する。
- この導線は照合の完了・未完了を問わず「データ DL」1 つとし、状態でラベルを変えない。ボタンとして、行内の同じ位置（照合開始の右）に置く（`01_admin_common_ui.md` §4.6）。照合が完了した行には照合開始を置かず、左のスロットを空ける。
- 現行画面は「完成データ確認」と「全レコードDL」を別のボタンとして併置するが、いずれも同じ 3 種類のファイルの取得に帰着するため、本書ではモーダルへまとめて 1 つの導線とする。
- 行を押下すると名刺情報照合（SCR-A-013）へ遷移する。行内の操作は行の押下と分離する（`01_admin_common_ui.md` §4.5）。
- ダウンロードの出力形式と文字コードは `01_admin_common_ui.md` §10 に従う。
- ダウンロードは監査ログの記録対象（データ持ち出し）とする（`02_admin_common_audit_log.md` §3）。
- 照合を開始できるのは、未完了かつ未ロックの照合対象が 1 件以上あるアンケートに限る。該当が 0 件のアンケートでは開始操作を非活性とする。未完了の名刺がすべて他の担当のロック中である場合も 0 件として扱う。

### 4.6 追加要件（あったほうが良い）

次の 2 件は、§4.1〜§4.5 が満たされたうえで追加する要件とする。

| 要件 | 内容 |
| --- | --- |
| アンケートを指定した照合の開始 | 出題順によらず、アンケート ID を指定して当該アンケートの未照合の名刺から照合を開始する |
| 止まっている照合の検知 | 一定時間進んでいない照合を一覧上で識別できるようにする（検討中。判定条件は未定） |

## 5. 通知

本画面の操作を起点とする通知・メールの発火はない（`03_admin_common_notifications.md` §2）。

## 6. 権限とデータ範囲

| 権限レベル | 扱い |
| --- | --- |
| Lv1 | 本画面へアクセスできない。サイドバーに項目を表示しない |
| Lv2 | 自グループのアンケートのみを表示・操作できる。集計サマリも自グループの範囲で算出する |
| Lv3 | 全グループのアンケートを表示・操作できる |
| Lv4 | 全グループのアンケートを表示・操作できる |

- 権限判定とデータ範囲の絞り込みはサーバー側で行う（`00_admin_common_permissions.md` §9.1）。
- Lv2 が他グループのアンケート ID を直接指定して検索した場合も、結果に含めない。
- 会社名の列と会社名による検索は Lv3 以上にのみ表示する。Lv2 は照合作業に必要なアンケート ID・納期区分までを扱い、顧客の識別情報は扱わない（`00_admin_common_permissions.md` §3.3）。列の並びは権限で変わり、Lv2 以下では会社名の列を詰めて表示する。

## 7. 状態と挙動

### 7.1 初期表示

- 検索条件は未入力、作業ステータスの絞り込みは「すべて」の状態で表示する。
- 一覧の既定の並び順は納期日時の昇順とし、納期が近いアンケートを先頭に表示する。
- 表示件数の既定は 50 件とする。

### 7.2 該当が 0 件の場合

- 一覧の位置に該当なしの旨を表示する。集計サマリは 0 を表示する。

### 7.3 集計値の反映

- 総件数・未入力・一致・不一致および集計サマリは、最大 5 分の反映遅延を許容する（`05_admin_nonfunctional.md` §2）。
- 画面には集計の最終更新日時を表示する。

### 7.4 名刺情報照合からの復帰

- 名刺情報照合から戻った場合、直前の検索条件・絞り込み条件・ページ位置を保持した状態で一覧を再表示する。
- 一覧の件数は再取得した値で表示する。

## 10. 画面確認観点

モックアップ上で次を確認する。

- [ ] 集計サマリが数値カードとして表示され、集計の最終更新日時が併せて表示される
- [ ] 一覧にアンケート ID、タイトル、会社名、納期区分、会期、総件数、未入力、一致、不一致、進捗、納期日時が表示される
- [ ] 件数が 3 桁ごとのカンマ区切り、納期日時が `YYYY/MM/DD HH:MM` で表示される
- [ ] アンケート ID、ユーザー ID、会社名による検索と、作業ステータス・納期区分による絞り込みが機能する
- [ ] アンケート ID、ユーザー ID、作業ステータス、納期日時の各列見出しで並び替えができる
- [ ] 初期表示の並び順が納期日時の昇順である
- [ ] 納期日時を過ぎたアンケートが一覧上で区別して表示される
- [ ] 照合開始で対象アンケートの名刺情報照合へ遷移する
- [ ] 照合対象が 0 件のアンケートで照合開始が非活性になる
- [ ] データ DL のモーダルから完成データ CSV・全レコード CSV・回答データ CSV・名刺画像（ZIP）を選択できる
- [ ] 該当が 0 件のとき、一覧に該当なしの旨が表示され、集計サマリが 0 を表示する
- [ ] 1366px の幅で一覧に横スクロールが出ず、隠れた列の分だけ他の列がずれない
- [ ] Lv2 でログインした場合、一覧に会社名の列と会社名の検索欄が表示されず、他の列がずれない
- [ ] Lv2 でログインした場合、他グループのアンケートが一覧・検索結果・集計サマリのいずれにも現れない
- [ ] Lv1 でログインした場合、本画面の URL へ直接アクセスしても表示されない

## 11. 画面外の確認事項

| # | 項目 | 内容 |
| --- | --- | --- |
| 1 | 検索キーの差分 | 本書は検索キーをアンケート ID・ユーザー ID・会社名（Lv3 以上）とするが、現行画面はアンケート ID・氏名・会社名で検索する。残る差分は氏名の有無である。氏名を検索キーに加えるかを確定する。 |
| 2 | ユーザー ID と作業ステータスの表示 | ユーザー ID と作業ステータスを検索・絞り込みの条件とする一方、§4.4 の表示項目には含めていない。絞り込み結果を画面上で確認できないため、一覧へ列を追加するか、条件専用のキーとするかを確定する。 |
| 3 | 作業ステータスの値集合 | たたき台の 4 値（会期前 / 会期中 / データ化中 / データ化完了）、現行画面 `/admin/matching_list` の 6 値（会期前始まり）、現行画面 `/admin/surveys` の 6 値（作成中始まり）を突き合わせ、正とする値集合と各値の判定条件を確定する。`13_admin_survey_management.md` §11 の #3、`04_admin_common_glossary.md` §8 の #2 と同一の論点である。 |
| 4 | 一覧の表示形式 | 表形式とカード形式のどちらを採用するかを確定する。1 画面あたりの表示件数と、納期日時での一覧性を判断基準とする。 |
| 5 | 完了件数の定義 | 進捗表示の分子を「一致 + 不一致」とするか「一致のみ」とするかを確定する。不一致は修正入力を経て確定するため、進捗の意味が変わる。入力の確定条件（`20_admin_data_input_form.md` §11 の #2）、照合の一致・不一致判定（`22_admin_matching_form.md` §11 の #2）、オペレーター実績確認の正答率の分母（`24_admin_achievements.md` §11 の #1・#2）と併せて、本項を含む 4 点を同一の定義で確定する。 |
| 6 | エスカレーション導線の扱い | 現行画面が持つエスカレーション確認の導線と、集計サマリのエスカレーション件数を、凍結期間中どう扱うかを確定する。 |
| 7 | Lv1 のアクセス | 本書は Lv1 をアクセス不可として定義する。照合作業に Lv1 が関与しない前提で確定してよいかを確認する。 |
| 8 | 完成データの出力項目 | 完成データと全レコードの出力項目、および読み取れなかった項目の表記を確定する。 |
| 9 | 止まっている照合の判定条件 | §4.6 の検知を導入する場合、何時間進んでいない状態を対象とするかを確定する。 |
| 10 | 照合ロックとの関係 | 名刺情報照合のロック（現行は約 200 秒で自動解除）中のアンケートを、一覧上で識別できるようにするかを確定する。 |
