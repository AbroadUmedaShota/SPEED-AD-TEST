## 1. 文書目的

- 本書は、管理者画面の権限レベル、画面ごとのアクセス範囲、操作単位の権限差、グループによるデータ分離を定義する。
- 画面別ファイルは本書を参照し、画面固有の差分のみを各ファイルに記載する。
- 利用者向け画面の権限は本書の対象外とし、`docs/リライト版仕様書/user/` で扱う。

## 2. 権限レベルとロール

管理者画面の権限は Lv1 から Lv4 の 4 段階とする。Lv の数値が大きいほど広い範囲を扱う。

| 権限レベル | ロール表記 | 主な役割 |
| --- | --- | --- |
| Lv1 | Operator | 名刺データの入力作業を行う作業者 |
| Lv2 | OperatorAdmin | 作業グループの管理者。照合作業、アサイン、配下アカウントの管理を行う |
| Lv3 | Admin | 運営管理者。顧客・アンケート・請求・ログを含む全範囲を扱う |
| Lv4 | MasterAdmin | 最上位管理者。Lv3 の範囲に加え、パスワードの直接設定を行う |

ロール表記はたたき台の記載をそのまま用いる。正式名称は確定前であり、本書では暫定の表記として扱う（※要確定・§10）。

画面単位で見える範囲は Lv3 と Lv4 で同一とする。両者の差は §4 の操作単位の権限差にのみ現れる。

一方で、作業系画面（データ入力対象一覧・名刺入力画面・照合結果一覧・名刺情報照合）では、Lv1・Lv2 が作業対象の名刺と、その名刺が属するアンケートの情報を扱う。顧客情報に一切触れないという意味ではない。作業対象として扱える範囲は §5 のデータ範囲に従う。

## 4. 操作単位の権限差

画面へのアクセスとは別に、次の操作は実行できる権限レベルを個別に定める。

| 操作 | 実行できる権限レベル | 付帯条件 |
| --- | --- | --- |
| パスワードの管理者直接設定 | Lv4 のみ | 実行時に理由の入力を必須とする。実行後に対象本人へ通知メールを送信する |
| パスワード初期化メールの送信 | Lv2 以上（自身の操作範囲内） | 対象本人へ初期化メールを送信する。対象が利用者の場合は Lv3 以上とする（ユーザー詳細のアクセス権限に従う） |
| グループ（会社・法人単位）の作成 | Lv3 以上 | — |
| オペレーターの招待 | Lv2 以上 | 仮アカウント発行と招待リンク送信を伴う（§7）。付与できる権限レベルは制限せず Lv1〜Lv4 から選択する（2026-08-28 確定・`23_admin_operator_management.md` §4.4） |
| オペレーターの権限レベル変更 | Lv2 以上（自身のデータ範囲内） | 操作者と対象の権限レベルの上下関係による制約は設けない。自分自身も対象にできる（2026-08-28 確定・`23_admin_operator_management.md` §4.4） |
| 営業日（定休日・休業日・振替営業日）の設定変更 | Lv3 以上 | Lv2 はキャパ調整とアサイン運用のみ行う |

Lv2 が操作できる対象アカウントは、同一グループ内の全アカウントとする（権限レベルを問わない。2026-08-28 確定・`23_admin_operator_management.md` §6）。

## 5. グループとデータ範囲

- グループは会社・法人を単位とする。Abroad 本体も 1 つのグループとして扱う。
- Lv1 および Lv2 は自グループのデータのみを扱う。他グループのデータは一覧・検索結果・集計のいずれにも含めない。
- Lv3 および Lv4 は全グループのデータを扱う。
- グループの作成は Lv3 以上が行う（§4）。

参考: 現行モック `03_admin/operator-management.html` および現行画面 `/admin/operator_list` では、所属がチーム A / B / C 単位で管理されている。会社・法人単位への変更に伴う既存データの移行方針は確定前とする（※要確定・§10）。

名刺入力作業で用いる「作業グループ①〜⑧」は、名刺データ化の入力項目をまとめた単位であり、本章のグループ（会社・法人単位）とは別の概念である。用語の区別は `04_admin_common_glossary.md` §2 で定義する。

## 6. 権限による画面表示の制御

- サイドバーには、ログイン中のアカウントがアクセスできる画面のみを表示する。
- アクセスできない画面の URL へ直接アクセスした場合は、画面を表示せずダッシュボードへ遷移させる。
- 画面内で、権限が不足する操作のボタン・リンクは非表示とする。表示したうえで押下時に拒否する方式は取らない。
- データ範囲が「自グループのみ」の場合、一覧・検索・集計のいずれも自グループのデータのみを対象とする。総件数、進捗率などの集計値も自グループの範囲で算出する。

参考: 現行モックは遷移させず、`03_admin/src/proto-level.js` が画面本文をアクセスできない旨の表示へ差し替える。権限レベルを切り替えて画面ごとの差を確認するための代替であり、本番の挙動は上記のダッシュボードへの遷移とする。

## 7. アカウント状態と招待

### 7.1 アカウント状態

オペレーターアカウントの状態は次の 3 値とする。

| 状態 | 意味 | ログイン |
| --- | --- | --- |
| 有効 | 通常に稼働しているアカウント | 可 |
| 無効 | 稼働を停止したアカウント。退職者は本状態で管理する | 不可 |
| 招待中 | 招待メールを送信し、本人の登録完了を待っている仮アカウント | 招待リンクからの登録のみ可 |

画面上の操作は無効化に寄せる。論理削除は内部フラグとして別に管理し、画面からは操作しない。

### 7.2 招待フロー

1. 招待を実行すると、対象のメールアドレスに対して仮アカウントを作成し、状態を「招待中」とする。
2. 招待メールに含める登録リンクの有効期限は発行から 72 時間とする。利用者側の招待仕様（AD-02 系）と同一の有効期限とする。
3. 本人が期限内に登録を完了すると、状態は「有効」へ移る。
4. 招待中のアカウントに対しては、招待メールの再送とキャンセルを実行できる。再送時は新しいリンクを発行し、有効期限を再度 72 時間とする。
5. キャンセルすると発行済みリンクは無効になる。キャンセル後の仮アカウントを削除するか、別の状態として残すかは確定前とする（※要確定・§10）。

利用者アカウントの招待も同一の方式とする。発火するメールは `03_admin_common_notifications.md` で定義する。

### 7.3 パスワード管理

パスワードの管理は次の 2 系統とする。

| 系統 | 実行者 | 動作 |
| --- | --- | --- |
| 初期化メール | Lv2 以上 | 対象本人へパスワード初期化メールを送信し、本人が新パスワードを設定する |
| 管理者直接設定 | Lv4 のみ | 管理者が新パスワードを直接設定する。理由の入力を必須とし、実行後に対象本人へ通知メールを送信する |

いずれの系統も監査ログの記録対象とする（`02_admin_common_audit_log.md`）。

## 8. 対応可能言語

- オペレーターに設定する対応可能言語は DB のマスタで管理する。
- オペレーター管理画面では、マスタに登録済みの言語から複数選択して設定する。
- 言語マスタへの追加・変更は開発側が DB を直接更新する運用とする。

参考: 現行画面 `/admin/operator_list` の新規登録では、日本語・英語・中国語簡体字・中国語繁体字の複数選択が可能である。

## 9. 本番化要件

### 9.1 認可の実装方針

- 権限判定はサーバー側で行う。画面側の表示制御は補助であり、権限判定の根拠としない。
- データ範囲（自グループのみ／全範囲）の絞り込みは、一覧取得・検索・集計・出力のすべての経路に適用する。
- 直接 URL アクセス、API の直接呼び出しのいずれにおいても、対象データの所属グループを検証する。

### 9.2 受け入れ基準

- [ ] Lv1 でログインし、§3 で「—」とした画面の URL へ直接アクセスしても画面が表示されない
- [ ] Lv2 でログインし、他グループのデータが一覧・検索結果・集計値のいずれにも現れない
- [ ] Lv3 でパスワードの管理者直接設定の操作要素が表示されない
- [ ] Lv4 でパスワードを直接設定すると、理由入力が必須になり、本人へ通知メールが送信される
- [ ] 招待リンクが発行から 72 時間経過後に無効になる
- [ ] 招待をキャンセルすると、発行済みリンクからの登録が拒否される
