# 管理者画面 用語・ステータス値定義（共通編）

## 1. 文書目的

- 本書は、管理者画面の要件定義書で用いる用語と、画面に表示するステータス値を定義する。
- 画面別ファイルは本書の用語を用いる。同義の別表記を各ファイルで新たに導入しない。
- 正式名称が確定していない用語は「※要確定」を付し、確定するまで本書の表記を暫定として用いる。

## 2. 組織・アカウント

| 用語 | 定義 |
| --- | --- |
| 権限レベル（Lv1〜Lv4） | 管理者画面のアクセス範囲と操作範囲を決める 4 段階の区分。定義は `00_admin_common_permissions.md` §2 |
| Operator / OperatorAdmin / Admin / MasterAdmin | Lv1 / Lv2 / Lv3 / Lv4 に対応するロール表記。正式名称は確定前（※要確定・§8） |
| グループ | オペレーターが所属する会社・法人の単位。データ範囲の分離単位でもある。Abroad 本体も 1 グループとして扱う |
| 作業グループ（グループ①〜⑧） | 名刺データ化の入力項目をまとめた単位。①メールアドレス、②姓・名、③会社名・部署名・役職名、④郵便番号・住所 1・住所 2、⑤電話番号 1・電話番号 2・携帯番号・FAX 番号、⑥ URL、⑦その他メモ、⑧フリー入力の 8 区分とし、項目構成は `20_admin_data_input_form.md` §4.4 に従う。1 枚の名刺は複数の作業グループを通過して入力される。会社・法人単位の「グループ」とは別の概念 |
| オペレーター | 管理者画面にログインする運営側アカウントの総称。Lv1〜Lv4 のいずれかの権限レベルを持つ（`00_admin_common_permissions.md` §2）。名刺データの入力・照合を行う作業者に限らず、運営管理者（Lv3）と最上位管理者（Lv4）を含む |
| 利用者 | SPEED AD を利用する顧客側のアカウント。本文では「利用者」と表記し、画面上の項目名・画面名では「ユーザー」と表記する（例: ユーザー ID、ユーザー管理） |
| 顧客・会社 | SPEED AD を利用する契約主体 |
| 代行変更 | 管理者が利用者に代わって設定・データを変更する操作 |
| 監査ログ | 運営側の操作の記録。全操作を時系列で見る横断ビュー（サイドバーの「監査ログ」画面）と、対象ごとに抽出した個別ログの 2 系統があり、同一のデータを参照する（`02_admin_common_audit_log.md` §2）。画面名・見出しとも「監査ログ」で統一し、「操作ログ」とは呼ばない |

「グループ」は会社・法人単位を指し、入力項目の分割単位は「作業グループ」と表記して区別する。表示ラベル上の呼称は確定前とする（※要確定・§8）。

## 3. アンケート・案件

| 用語 | 定義 |
| --- | --- |
| アンケート | 回答収集・名刺データ化・請求の中心となる案件単位 |
| アンケート ID | アンケートを一意に識別する ID |
| 会期 | アンケートが回答を受け付ける期間。開始日と終了日を持つ。日付のみで扱い、時刻は持たない。終了日は当日 23:59 まで回答を受け付ける |
| 会期前 / 会期中 / 会期終了 | 現在日時と会期の関係を表す区分 |
| 設問 | アンケートを構成する質問項目 |
| 回答 | 回答者が送信した 1 件分のデータ |
| 公開後の設問変更 | 会期開始後から会期終了までの間に、アンケートの設問構成を変更する操作。通常の編集と分離して扱う。会期終了後の変更可否は `14_admin_survey_detail.md` §2.1 の会期状態別の操作可否に従う |
| プレミアム | 利用者側の月額上位プラン（月額 10,000 円・税別）。納期の優先順位はデータ化申込プランで決まり、本プランとは独立する |
| データ化申込プラン | 名刺データ化の申込内容。納期の区分を含む |

## 4. 名刺データ化

| 用語 | 定義 |
| --- | --- |
| 名刺データ化 | 回答に添付された名刺画像を、項目ごとのテキストデータへ変換する一連の作業 |
| 入力 | オペレーターが名刺画像を見て項目を入力する作業 |
| オペレーター入力 1〜3 | 同一の名刺に対する複数オペレーターの入力結果 |
| OCR 結果 | 名刺画像から機械的に読み取った結果 |
| 照合 | 複数の入力結果と OCR 結果を突き合わせ、正しいデータを確定する作業 |
| 一致 | 照合対象の値が突き合わせの結果で一致している状態 |
| 不一致 | 照合対象の値が突き合わせの結果で一致していない状態。修正入力の対象となる |
| 未入力 | 入力作業がまだ完了していない状態 |
| 修正入力 | 不一致項目に対して照合担当が正しい値を入力する操作 |
| 完成データ | 照合が完了し、顧客へ納品できる状態のデータ |
| 全レコード | 照合の途中経過を含む、対象アンケートの全データ |
| スキップ | 入力作業中に、判断できない名刺を後回しにする操作 |
| 照合ロック | 照合中の名刺を他の担当が同時に扱えないようにする排他状態 |
| エスカレーション | 通常フローで処理できない名刺を例外として引き上げる扱い。画面としての検討は凍結中 |
| 納期日時 | 完成データを納品する期限。営業日カレンダーの設定を前提に算出する。本文の用語は「納期日時」に統一する。「納品期日」は現行画面 `/admin/matching_list` 上の表記であり、同一の概念を指す |
| データ化完了予定日 | 名刺データ化の完了見込み日。請求管理（SCR-A-006）の一覧に表示する。納期日時と同一の概念か、納期日時より前に置く内部の目安かは確定前（※要確定・§8） |
| 納期区分 | 納期の優先順位を表す区分。優先度の高い順に オンデマンド、超特急、特急、通常、お試し（お試しの位置は※要確定）。区分名と単価（お試し 0 円／通常 50 円／特急 100 円／超特急 150 円／オンデマンド 200 円）は利用者側画面の定義と一致させる |
| 完了データの手動アップロード | 通常の照合フローを経ずに、完成データを管理者が直接取り込む操作。障害時の代替手段として用いる |
| データ化対象の名刺 | あるアンケートで名刺データ化の対象となる名刺の総数。アンケート詳細（SCR-A-005）§4.4 の「データ化対象の名刺」と、照合結果一覧（SCR-A-011 / SCR-A-012）§4.4 の「総件数」は同じ数を指す。両画面で違う数を出さない |
| 実際の件数 | 請求の対象として確定した名刺の件数（`15_admin_billing.md` §4.2）。データ化が完了した分だけを数えるため、データ化の途中では「データ化対象の名刺」より少なくなる。完了後は一致する |
| 回答数 | アンケートに対する回答の数。名刺の件数とは別の数であり、名刺が添付されていない回答も含む |

## 5. 請求

| 用語 | 定義 |
| --- | --- |
| 請求 | アンケート単位または会社単位で発生する利用料金 |
| 請求書 | アカウントと発行月の組み合わせで作成する書面 |
| プレミアム利用料 | 請求内訳のうち、プレミアムプランの契約に基づく定額分（月額 10,000 円・税別）。利用者側の請求書が使う明細名に合わせる |
| お礼メール送信費用 | 請求内訳のうち、お礼メール送信数に対する従量分（1 通 1 円・無料 100 件を控除）。利用者側画面の費目名と一致させる |
| 請求合計 | プレミアム利用料・名刺データ化費用・お礼メール送信費用・クーポン値引きを合算した金額 |
| クーポン | 割引を適用するための発行単位。割引率、使用可能期限、使用可能回数を持つ |

請求書とアンケートの単位関係は確定前とする（※要確定・§8）。

## 6. ステータス値

### 6.1 アカウント状態

アカウント状態はオペレーターと利用者で別の値集合を持つ。

オペレーターアカウントの状態は次の 3 値とする（オペレーター管理・SCR-A-014）。

| 値 | 意味 |
| --- | --- |
| 有効 | 通常に稼働している |
| 無効 | 稼働を停止している。退職者は本状態で管理する |
| 招待中 | 招待メールを送信し、本人の登録完了を待っている |

利用者アカウントの状態は次の 4 値とする（ユーザー管理・SCR-A-002）。

| 値 | 意味 |
| --- | --- |
| 有効 | 通常に稼働している |
| 停止 | 運営側が稼働を停止している。ログインできない |
| 招待中 | 招待メールを送信し、本人の登録完了を待っている |
| 本登録未了 | 仮登録から本登録へ進んでいない |

- 利用者側の「停止」とオペレーター側の「無効」は同種の概念だが語が異なる。表記を統一するかは §8 で確定する。
- 「招待中」と「本登録未了」は状態が重なる。招待中のアカウントは本登録未了でもある。単一の状態値として扱うか、別の属性として持つかは §8 で確定する。

### 6.2 作業ステータス

アンケート単位の名刺データ化の進み具合を表す区分。現時点で 3 通りの値集合が併存しており、正とする集合は確定前とする（※要確定・§8）。

| 出典 | 値集合 |
| --- | --- |
| たたき台（本要件の検索・絞り込み条件） | 会期前 / 会期中 / データ化中 / データ化完了 |
| 現行画面 `/admin/matching_list` の絞り込み | 会期前 / 会期中 / データ化中 / アップ待ち / アップ完了 / データ化なし |
| 現行画面 `/admin/surveys` の絞り込み | 作成中 / 会期中 / データ化中 / アップ待ち / アップ完了 / データ化なし |
| 参考: 現行モック `03_admin/reconciliation/index.html` | 会期前 / 会期中 / 会期中オンデマンド / 会期終了（データ化無し） / 会期終了（データ化中） / 会期終了（照合待ち） / エスカレ |

現行の 2 画面は 6 値で構成が揃うが、先頭の値が「会期前」と「作成中」で異なる。会期開始前のアンケートを、会期を基準に表すか作成の進行状態で表すかが画面間で一致していない。

集合間の対応関係のうち、たたき台の「データ化完了」が現行の「アップ待ち」「アップ完了」のいずれに対応するか、「データ化なし」に相当する値をたたき台側に持つか、「作成中」と「会期前」を同一の状態とみなすかが未整理である。値集合を確定したうえで、本節を単一の表へ置き換える。

## 7. 表記の統一

- 画面名は `README.md` のファイル構成表に記載した名称を用いる。
- 権限は「Lv1」「Lv2」の形式で表記する。「レベル 1」「level1」の表記は用いない。
- 日時・件数・金額の表記形式は `01_admin_common_ui.md` §9 に従う。
- 運営側の操作記録は「監査ログ」と表記する。「操作ログ」は用いない（§2）。
- 名刺の件数は「データ化対象の名刺」「実際の件数」「回答数」を区別して用いる（§4）。同じアンケートに対して画面ごとに違う数を出さない。

## 8. 画面外の確認事項

| # | 項目 | 内容 |
| --- | --- | --- |
| 1 | ロールの正式名称 | Operator / OperatorAdmin / Admin / MasterAdmin の正式名称と画面表示名を確定する。 |
| 2 | 作業ステータスの値集合 | §6.2 の各集合を突き合わせ、正とする値集合と各値の判定条件を確定する。現行 2 画面で先頭の値が「会期前」と「作成中」に分かれている点を含めて決める。強制停止したアンケートを表す状態値を持つかを併せて決める（`13_admin_survey_management.md` §11 の #7）。 |
| 3 | グループの呼称 | 会社・法人単位の「グループ」と作業単位の「作業グループ」について、画面上の表示ラベルを確定する。 |
| 4 | 請求書の単位 | 請求書がアカウントと発行月の組み合わせで確定する前提のもと、アンケート単位の請求とどう対応するかを確定する。 |
| 5 | 納期区分「お試し」の優先位置 | 出題・納期の優先順位においてお試しをどこに置くかを確定する。区分名は利用者側画面（オンデマンド・超特急・特急・通常・お試し）と一致済み。 |
| 6 | 未読取項目の表記 | 名刺から読み取れない項目に用いる記号（現行運用は「〓」）を、完成データおよび CSV 出力でどう扱うかを確定する。 |
| 7 | アカウント状態の表記統一 | §6.1 の 2 表について、利用者側の「停止」とオペレーター側の「無効」を同一の語へ統一するかを確定する。あわせて、利用者側の「招待中」と「本登録未了」を単一の状態値とするか別属性として持つかを決める。`11_admin_user_management.md` §11 の #2 と連動する。 |
| 8 | データ化完了予定日と納期日時の関係 | §4 の「データ化完了予定日」が納期日時と同一の概念かを確定する。別概念であれば、算出根拠と表示先の使い分けを定める。`15_admin_billing.md` §11 の #7 と連動する。 |
