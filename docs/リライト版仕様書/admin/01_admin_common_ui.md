# 管理者画面 共通 UI 規則（共通編）

| 項目 | 値 |

## 1. 文書目的

- 本書は、管理者画面の全画面に共通する画面骨格、一覧の操作規則、表記規則、出力規則を定義する。
- 画面別ファイルは本書を参照し、画面固有の要件のみを記載する。共通規則を各画面で再定義しない。
- 配色、フォント、コンポーネントの実装形式は本書の対象外とする。

## 2. 画面骨格

すべての管理者画面は次の 4 領域で構成する。

| 領域 | 内容 |
| --- | --- |
| ヘッダー | 画面上部に固定表示する。サービスロゴを配置する |
| サイドバー | 画面左に固定表示する。ログイン中アカウントのメールアドレスと権限表示、ナビゲーション、ログアウトを配置する |
| メインコンテンツ | パンくず、画面タイトル、画面固有の内容を配置する |

- 画面タイトルはメインコンテンツ上部に表示し、下部を区切り線で仕切る。
- パンくずは画面タイトルの上に表示し、階層をたどって上位画面へ戻れるようにする。
- 個票・作業画面（名刺入力画面、名刺情報照合）は、誤操作を防ぐためサイドバーを表示しない。離脱の導線は「一覧へ戻る」ボタンとする。主要領域は縦スクロールなしで 1 画面に収める。

参考: 現行モック `03_admin/common/sidebar.html` はヘッダー・サイドバーを共通パーツとして各画面に読み込んでいる。

## 3. サイドバーのナビゲーション

- ナビゲーションには、ログイン中アカウントがアクセスできる画面のみを表示する。表示条件は `00_admin_common_permissions.md` §3 に従う。
- ナビゲーション項目には画面名を表示する。現在表示中の画面の項目は選択状態として区別する。
- ナビゲーションの末尾にログアウトを配置する。
- 画面名は現行画面の呼称をそのまま使う。
- 名刺入力と照合は、ナビゲーションの項目名と遷移先の画面の見出しが現行画面でも異なる。ナビゲーションは「名刺入力画面」「照合画面」とし、遷移先の一覧の見出しは「データ入力対象一覧」「照合結果一覧」、その先の個別画面の見出しは「名刺入力画面」「名刺情報照合」とする。
- ユーザー管理だけは現行画面と表記を変える。現行画面のナビゲーションは「ユーザー(利用者)管理」だが、本書は括弧書きを外して「ユーザー管理」とする（2026-08-04 のユーザー判断）。「ユーザー」と「利用者」の使い分けは `docs/glossary_用語洗い出し.md` の A-14 で未確定であり、そちらの確定後に本文の語も併せて見直す。

参考: 現行画面 `/admin` のナビゲーションは、ユーザー(利用者)管理／アンケート管理／請求管理／クーポン管理／営業日カレンダー／請求書管理／名刺入力画面／照合画面／オペレーター管理／オペレーター実績確認の 10 項目である（`03_admin/BY-221_照合画面/BY-222/BY-222.html`）。本書はこれにダッシュボードと監査ログを加えた 12 項目とする。

## 4. 一覧画面の共通規則

一覧を持つ画面は、次の規則を共通で満たす。

### 4.1 検索と絞り込み

- 検索条件の入力欄と絞り込み条件の選択欄は、一覧の上部にまとめて配置する。
- 検索条件は画面ごとに定める。複数の検索キーを 1 つの入力欄でまとめて扱う場合は、対象とするキーをプレースホルダに明示する。
- 絞り込み条件は選択式とし、初期値は「すべて」とする。
- 入力した条件は「検索」の操作で一覧へ適用する。複数の条件を指定した場合はすべてを満たす行を残す。
- 条件をまとめて初期状態へ戻す操作を用意する。この操作では入力欄と適用中の条件の両方を解除し、全件表示へ戻す。
- 条件を変更した結果、該当が 0 件の場合は、一覧の位置に該当なしの旨を表示する。あわせて、条件を変更するか初期状態へ戻せば全件に戻せることを示す。

#### 4.1.1 他画面から引き継いだ絞り込み

- 他画面の集計値・リンクから遷移した一覧は、遷移元が指定した条件で絞り込んだ状態で開く。引き継ぐ条件は遷移先画面の URL のクエリとして渡し、遷移先の絞り込み欄にも同じ値を表示する。
- 引き継げる条件は一覧ごとに定める。定めのないクエリは無視し、全件表示のまま開く。
- 絞り込みが適用されている間は、一覧の直上に適用中の条件（項目名と値）と解除の操作を表示する。解除は §4.1 の初期状態へ戻す操作と同じ結果とする。
- どの一覧がどの条件を受け取るかは画面別ファイルの導線に従う。

### 4.2 並び替え

- 並び替えを提供する列は、列見出しの押下で昇順・降順を切り替える。
- 現在の並び替え対象列と方向は、列見出し上で判別できるようにする。

### 4.3 ページング

- 一覧は既定で 1 ページあたり 50 件を表示する。表示件数は 50 件・100 件・150 件から選択できる。
- ページ番号、前ページ、次ページの操作を一覧の下部に配置する。
- 先頭ページで前ページ、最終ページで次ページの操作は淡色で表示し、送り先がないことを示す。
- 全体件数と現在の表示範囲を数値で表示する。
- 絞り込みが適用されている場合、全体件数・表示範囲・ページ番号・表示件数の切替は、いずれも絞り込み後の行を対象とする。表示件数を切り替えた場合はページ番号を作り直し、先頭ページを表示する。

参考: 現行モック `03_admin/reconciliation/index.html` は表示件数 50 / 100 / 150 の選択とページ番号操作を備える。

### 4.4 読込中と取得失敗の表示状態

一覧と集計領域は、データの取得状況に応じて次の表示状態を持つ。モックアップでは各状態を表示状態として作成する。

| 状態 | 表示 |
| --- | --- |
| 初回読込中 | 一覧・集計領域の位置に読込中である旨を表示する。検索・絞り込み・並び替え・ページングの操作は受け付けない |
| 再読込中 | 直前に表示していた内容を維持したまま、読込中である旨を示す |
| 取得失敗 | 取得に失敗した旨と再試行の操作を表示する。直前に表示していた内容がある場合は維持する |
| 集計のみ失敗 | 一覧は取得した内容を表示し、集計領域にのみ取得に失敗した旨と再試行の操作を表示する |

- 該当が 0 件の状態（§4.1）と取得失敗の状態は、表示上で区別する。
- 再試行の操作は、失敗した領域の内側に配置する。

### 4.5 行の押下

- 一覧の行を押下したとき、その行の主対象を開く。主対象が何か（詳細画面、個票、編集モーダル）は画面別ファイルで定める。
- 遷移先には押下した行の対象を引き継ぎ、その対象の識別情報を表示する。詳細画面へ遷移する場合は §4.1.1 と同じくクエリとして渡す。
- 行内に置いた個別の操作（詳細、削除、ダウンロードなど）を押下した場合は、その操作だけを実行し、行の押下による遷移は起こさない。
- 主対象を持たない行では行の押下を無効とし、その行で実行できる操作のみをリンクとして提供する。招待中のアカウント行がこれに該当する（`11_admin_user_management.md` §4.7）。

### 4.6 行内の操作

- 行内の操作は一覧の右端に「操作」列としてまとめ、ボタンとして提供する。文字だけのリンクでは提供しない。
- 操作は幅の等しいスロットへ入れ、ボタンをスロットの幅いっぱいに広げる。ラベルの文字数で行ごとにボタンの大きさと右端の位置がずれるのを防ぐためである。
- スロットの並びは画面内で固定し、同じ役割の操作は行が変わっても同じスロットに置く。左のスロットに対象を開く操作（詳細、照合開始）、右のスロットに状態を変える操作と取得の操作（停止、取り消し、DL）を置く。
- 同じ操作のラベルを行の状態で変えない。データ化の完了・未完了を問わず「DL」とする（`13_admin_survey_management.md` §4.7、`21_admin_matching_list.md` §4.5）。
- 条件が整えば実行できる操作は、条件を満たさない間も淡色の無効状態で表示する。会期前のアンケートの照合開始がこれに該当する。
- 同じ操作は、行の状態が違ってもボタンの体裁を変えない。状態は作業ステータス列で示すため、ボタンの色で重ねて示さない。
- その行では発生しない操作は置かず、スロットを空けたままにする。残った操作を詰めて寄せない。お試しプランの請求行のクーポン適用と、照合が完了した行の照合開始がこれに該当する。

参考: 現行モック `03_admin/user-management.html` は、詳細・再送を左、停止・有効へ戻す・取り消しを右のスロットへ置く。

### 4.7 操作の結果の反映

- 一覧から実行した操作の結果は、実行した時点で一覧へ反映する。作成した行は先頭に現れ、状態を変えた行はその場で表示が変わり、取り消した行は一覧から消える。件数の表記とページも同時に引き直す。
- 実行して一覧の見た目が変わらない操作（メールの送信、パスワードの設定、ファイルの取得など）は、画面下部に短い通知を出して受け付けたことを示す。
- 追加した行は、もとからある同じ状態の行と同じ列構成・同じ体裁で表示する。行の高さ、セルの数、操作ボタンの位置と色を揃える。
- 必須の入力が満たされていない場合と、一意であるべき値が重複している場合は、実行せずモーダル内に理由を示す。
- 作成した値が選択肢として使われる場合、その値を持つ選択肢は画面内に複数あることがある。一部だけを更新すると、別の場所から選べない状態になる。作成時は同じ値の集合を持つ選択肢をすべて更新する。重複の判定も同じ範囲で行う。

## 5. 集計値の表示

- 集計値は数値カードまたは表として表示する。カードには項目名と数値を配置する。補足文を添えるかどうかと、その内容は画面別ファイルで定める。
- 進捗は「完了件数 / 総件数」の形式で数値表示し、併せて百分率を整数で表示する。
- 集計対象の範囲は、ログイン中アカウントのデータ範囲に従う（`00_admin_common_permissions.md` §5）。
- 集計値の反映には遅延を許容する（`05_admin_nonfunctional.md` §2）。画面には集計の最終更新日時を表示する。
- 集計値の取得中および取得に失敗した場合の表示は §4.4 に従う。

## 6. 詳細表示とモーダル

- 一覧から個別レコードの詳細を開く場合は、モーダルまたは詳細画面のいずれかとする。どちらを用いるかは画面別ファイルで定める。
- モーダルで開く場合も、押下した行の対象の識別情報をモーダル内に表示する。モーダルから他画面へ移動する操作は、その対象を引き継いだ状態で遷移させる。
- モーダルは背景をオーバーレイで覆い、閉じる操作を右上と画面外クリックの両方で提供する。
- モーダルを開いている間は背面の操作を受け付けず、キーボードの移動先もモーダル内に限る。
- 開いた直後の初期フォーカスは種別で分ける。削除・停止・ダウンロードなど、取り消せない操作や外部へ影響する操作の確認モーダルはキャンセルに置く。入力を伴うフォーム型のモーダルは先頭の入力欄に置く。
- モーダル内で編集を行った場合、閉じた後の一覧は更新後の値を表示する。
- 作業画面（名刺入力画面、名刺情報照合）はモーダルとせず、独立した画面とする。

## 7. 操作の確認と実行

### 7.1 確認ダイアログ

次に該当する操作は、実行前に確認ダイアログを表示する。ダイアログには対象の識別子（アンケート ID、ユーザー ID、アカウント名など）を明示する。

- データを削除する操作
- アカウントを無効化する操作
- 公開後のアンケートに対する変更
- 完了データの手動アップロード
- パスワードの管理者直接設定
- 請求金額・契約状態に影響する変更（プレミアム契約状態の変更、クーポンの事後適用）

### 7.2 理由の入力

パスワードの管理者直接設定は、確認ダイアログ内で理由の入力を必須とする。入力した理由は監査ログに記録する（`02_admin_common_audit_log.md`）。

理由の入力を必須とする操作では、理由が未入力の間、実行ボタンを非活性とする。

### 7.3 実行中の制御

- 実行ボタンは押下後に非活性化し、二重実行を防ぐ。
- 実行結果は画面上部に成功または失敗のメッセージとして表示する。失敗時は入力内容を保持する。

### 7.4 状態遷移の自動化（設計方針・2026-08-12 追加）

運営側（アブロード）は必要な時にしか管理者画面を触らない運用を前提とする。データから判定できる状態遷移は自動を既定とし、手動操作は例外時の道具として残す。

- 例: 増員募集の締切・再開はアサインの充足状態から自動で切り替える（`18_admin_calendar.md` §4.5.3）。完了データの手動アップロードは障害時の非常口とする（`13_admin_survey_management.md`）。
- 手動操作を残す場合は、それが例外操作であることを画面上の文言または操作の説明で示す。
- 自動遷移の結果が運営の判断と食い違ったときに上書きできることは妨げない。ただし上書きが状態と矛盾したら自動判定へ戻す。

## 8. 入力フォームの共通規則

- 必須項目にはラベル横に必須の表示を付ける。
- 入力エラーは該当欄の直下にメッセージを表示する。複数欄でエラーが発生した場合は、最初のエラー欄へフォーカスを移す。
- 保存せずに画面を離れようとした場合、入力内容がある間は確認ダイアログを表示する。
- 選択肢が DB マスタ由来の項目（対応可能言語など）は、マスタの登録内容から選択させる。

## 9. 表記規則

| 対象 | 表記 |
| --- | --- |
| 日付 | `YYYY/MM/DD` |
| 日時 | `YYYY/MM/DD HH:MM` |
| 件数 | 半角数字。3 桁ごとにカンマ区切り |
| 金額 | 半角数字。3 桁ごとにカンマ区切り。単位は「円」 |
| 割合 | 整数の百分率。単位は「%」 |
| 該当なし | 「—」 |

- 時刻は日本標準時（JST）で表示する。
- 納期など期限を持つ日時は、日付だけでなく時刻まで表示する。

## 10. ファイル出力

- CSV 出力を持つ画面は、出力操作を一覧の上部または集計領域に配置する。
- 出力対象は、その時点で適用されている検索条件・絞り込み条件の結果とする。ページングの表示範囲には限定しない。
- 文字コードは UTF-8（BOM 付き）とし、改行コードは CRLF とする。
- ファイル名には画面名と出力日時を含める。
- CSV および名刺画像の出力は監査ログの記録対象とする（`02_admin_common_audit_log.md`）。

## 11. 対応環境

対応ブラウザ、画面幅、アクセシビリティの扱いは `05_admin_nonfunctional.md` に従う。

## 12. 画面外の確認事項

| # | 項目 | 内容 |
| --- | --- | --- |
| 1 | 一覧の取得方式 | ページングをサーバー側で行うか画面側で行うかを確定する。件数が大きい画面（アンケート管理、名刺入力）ではサーバー側での絞り込みを前提とする。 |
| 2 | 集計の更新間隔 | 集計値の再計算タイミングと、画面に表示する最終更新日時の取得元を確定する。 |
| 3 | CSV の文字コード | UTF-8（BOM 付き）で表計算ソフトの想定利用に耐えるかを確認する。Shift_JIS の要望がある場合は出力時の選択可否を決める。 |
| 4 | 出力ファイルの保管 | CSV・名刺画像のダウンロードで生成するファイルをサーバー側に保管するか、都度生成するかを確定する。 |
| 5 | 詳細のモーダル採用範囲 | 実績個別詳細をモーダルとするか独立画面とするかを確定する（`24_admin_achievements.md` §11 の #8）。ユーザー詳細（SCR-A-003）とアンケート詳細（SCR-A-005）は独立画面として確定済みであり、本項の対象外とする。 |
| 6 | セッションタイムアウト | 無操作時のセッション有効時間と、作業画面（名刺入力画面・名刺情報照合）での延長方針を確定する。 |
| 7 | 一覧の同時更新 | 複数の管理者が同一データを同時に更新した場合の扱い（後勝ち／排他制御）を確定する。 |
