## 1. 文書目的

- 本書は、名刺 1 件ごとの照合を行う作業画面の要件を定義する。
- 全画面に共通する権限、UI 規則、監査ログ、通知、用語は共通編を参照する。本書は本画面に固有の要件を扱う。
- 照合対象アンケートの一覧と進捗管理は本書の対象外とし、`21_admin_matching_list.md` で扱う。

## 2. 画面概要

- OCR 結果と複数オペレーターの入力結果を項目ごとに見比べ、正しいデータを決める作業画面。
- 一致・不一致を識別表示し、不一致の項目にのみ修正入力を行う。
- データの最終決定は管理者（Lv2 以上）が行う。入力作業者の入力結果は候補であり、確定値ではない。
- 1 件あたりの判断回数が多いため、キーボードのみで一連の操作を完結できる構成とする。

## 3. 想定利用者と対象範囲

### 3.1 想定利用者

- 照合作業を行う Lv2（OperatorAdmin）。本画面の主たる利用者。
- 運営全体を管理する Lv3・Lv4。全グループの名刺を照合できる。

### 3.2 対象範囲

- 名刺画像（表裏同時表示）と画像操作
- 項目ごとの値の並列表示
- 一致・不一致の識別表示
- 不一致項目への修正入力と確定
- 照合中の排他制御（照合ロック）

### 3.3 対象外

- 照合対象アンケートの一覧・進捗・完成データの取得（`21_admin_matching_list.md`）
- 名刺データの入力作業（`20_admin_data_input_form.md`）
- 例外名刺の処理（エスカレーション画面 SCR-A-016 は検討凍結中）

## 4. 画面要件

### 4.1 共通構成

- 誤操作を防ぐためサイドバーは表示しない（`01_admin_common_ui.md` §2）。主要領域は縦スクロールなしで 1 画面に収める。離脱の導線は「一覧へ戻る」ボタンとする。
- 画面は上下 2 領域で構成する。上段に名刺画像（表・裏の横並び）、下段に項目の比較表を全幅で配置する。比較表は列数が多く、左右分割では長い値が折り返すため。
- 画面上部に、対象が属するアンケートのアンケート ID とタイトル、納期日時、データ化申込プランの納期区分を表示する。会社名は Lv3 以上にのみ表示する（§6）。
- 比較表は 1920 × 1080 の表示で 8 行が収まる高さとし、残りの高さを名刺画像へ割り当てる。9 行目は途中まで見える状態とし、続きがあることを示す。
- 確定操作と作業ロックの表示は画面上部にまとめる。比較表の下に操作の帯を置くと、その高さのぶんだけ表示できる行が減るため。

### 4.2 名刺画像の表示と操作

- 名刺の表と裏の画像を同時に表示する。上段の領域内に横並びで配置する。
- 各面の表示枠は上段の領域を左右で等分し、その幅いっぱいまで広げる。枠に固定の上限幅は設けない。入力画面（SCR-A-010）§4.2 と同じ考え方とする。
- 画像は枠の中で縦横比を保ったまま最大化する。名刺の縦横比と枠の縦横比は一致しないため、枠の左右または上下には地色が残る。
- 拡大した画像は自分の面の枠内で切り取る。表の拡大が裏の領域へ、裏の拡大が表の領域へはみ出さない。
- 画像に対して拡大、縮小、回転の操作を提供する。
- 画像はマウスオーバーでカーソル位置を起点に拡大表示し、クリックでその位置・倍率のまま固定できる（再クリックで解除）。拡大率は 1.0 倍から 4.0 倍の範囲を 0.5 刻みで調整し、初期値を 2.0 倍とする。入力画面（SCR-A-010）§4.2 と同じ操作体系とする。
- 画像操作はキーボードからも実行できるようにする。

### 4.3 項目の並列表示

各項目について、次の値を横に並べて表示する。

| 列 | 内容 |
| --- | --- |
| OCR 結果 | 名刺画像から機械的に読み取った値 |
| DB 値 | 既存データベースに保持している値（値の由来は §11 で確定） |
| 入力 1 | オペレーター 1 名目の入力値 |
| 入力 2 | オペレーター 2 名目の入力値 |
| 入力 3 | オペレーター 3 名目の入力値 |
| 修正入力 | 照合担当が入力する値 |
| 完成内容 | 確定後に採用される値 |
| 確定 | その項目の内容を確定したことを示すチェック（§4.5） |

- 項目は 1 行 1 項目として縦に並べ、列の並び順は上表のとおりとする。
- 値が存在しない列は「—」を表示する（`01_admin_common_ui.md` §9）。

### 4.4 一致・不一致の識別表示

- 各項目の状態を行単位で識別表示する。状態は「一致」「不一致（修正対象）」「確定済み」の 3 つとする。不一致の行には項目名の横に不一致である旨を併記する。
- 状態は色だけで示さない。不一致は項目名の横の併記で、確定済みは確定チェックが付いていることで、色を見なくても判別できるようにする。色と状態の対応は「画面の見かた」に置き、常時表示はしない。
- 不一致の件数を画面上部へ常に表示する。比較表は縦にスクロールするため、色分けだけではスクロールで隠れた不一致を見落とす。表示は「不一致 N / 全 M 項目」とし、不一致が 0 件のときは全項目が一致している旨を示す。
- 上部の不一致の件数は押下できるものとし、押すたびに次の不一致の行へ送って修正入力へフォーカスを移す。最後の行の次は先頭の不一致へ戻る。キーボードからも同じ操作を行える（入力欄の外で N キー）。
- 一致した項目は、一致した値をそのまま修正入力欄と完成内容へ採用し、確定チェックを付けた状態で初期表示する。
- 不一致の項目は、修正入力の対象として区別して表示する。確定チェックを付けた時点で「確定済み」へ移り、完成内容にその値を表示する。チェックを外すと元の状態へ戻る。
- 一致・不一致の判定条件は §11 で確定する。

### 4.5 修正入力と確定

- すべての項目に修正入力欄を置く。確定チェックが付いている間は編集できない状態とし、チェックを外すと編集できる状態へ戻す。一致と判定された項目も、チェックを外せば入力し直せる。
- 名刺から読み取れない箇所には「〓」を入力する。文字単位で用いる（`20_admin_data_input_form.md` §4.4）。
- 名刺に記載が無い項目は、修正入力欄を空のまま確定チェックを付ける。完成内容には「(記載なし)」と表示し、読み取れない「〓」とは区別する。
- 全項目に確定チェックが付いた状態で確定操作を行い、次の対象へ進む。付いていない項目が残っている間は確定操作を非活性とし、残件数を確定操作の隣に表示する。
- 見出し行に一括のチェックを置き、全項目の確定チェックをまとめて切り替えられるようにする。
- 確定操作の実行時は確認ダイアログを表示し、完成内容で確定する旨を明示する。記載なしとして確定する項目がある場合はその件数を併記する。
- 確定後は比較表のスクロール位置を先頭へ戻す。前の対象で下までスクロールした位置のまま次の対象を表示すると、先頭の項目を見落とすため。
- 修正入力欄の移動と確定はキーボード操作で実行できる。`Enter` は確定チェックが付いていない次の修正入力欄へ移動し、すべて確定済みであれば確定の操作へ移動する。`Alt + Enter` はフォーカス中の行の確定チェックを切り替える。
- 画面上部に「画面の見かた」を開く導線を置く。色と状態の対応、確定チェックの扱い、ショートカット一覧をここにまとめる。`?` からも開閉できる。
- 複写やチップ入力を 1 段戻す独自の取り消し操作（`Ctrl + Z`）は提供しない。入力欄の取り消しはブラウザ標準の動作に委ねる。

### 4.6 照合ロック

- 照合を開始した名刺はロックし、他の担当が同時に照合できない状態とする。
- 操作がないまま 3 分が経過した場合、ロックを自動解除して他の担当が照合できる状態へ戻す。
- ロックの解除後は名刺画像を伏せ、解除された旨と再取得の導線を表示する。解除された名刺は他の担当へ出題し直されるため、画像を見続けられる状態にしない。修正入力の内容は保持し、対象を再取得すればそのまま確定できる。
- ロック中に画面を離れた場合も、自動解除の時間経過をもってロックを解放する。

参考: 現行画面のロックは約 200 秒で自動解除される。3 分（180 秒）は現行値に近い区切りとして置いた暫定値であり、正式な解除時間は §11 で確定する。

## 6. 権限とデータ範囲

| 権限レベル | 扱い |
| --- | --- |
| Lv1 | 本画面へアクセスできない |
| Lv2 | 自グループの名刺のみを照合できる |
| Lv3 | 全グループの名刺を照合できる |
| Lv4 | 全グループの名刺を照合できる |

- 権限判定とデータ範囲の絞り込みはサーバー側で行う（`00_admin_common_permissions.md` §9.1）。
- 完成内容の決定はこの権限範囲でのみ行える。入力作業者（Lv1）は完成内容を決定しない。
- 画面上部の会社名は Lv3 以上にのみ表示する。Lv2 は照合作業に必要なアンケート ID・納期区分までを扱い、顧客の識別情報は扱わない（`00_admin_common_permissions.md` §3.3）。

## 7. 状態と挙動

### 7.1 初期表示

- 照合結果一覧から遷移した時点で、対象アンケートの照合対象を 1 件表示する。
- 不一致の項目が存在する場合、最初の不一致項目の修正入力欄にフォーカスを置く。
- 表示と同時に対象名刺をロックする。

### 7.2 確定後の遷移

- 確定すると完成内容を保存し、ロックを解放して次の対象を同一画面に表示する。
- 対象が残っていない場合は、その旨を表示し照合結果一覧へ戻る導線を提供する。

### 7.3 ロックの競合

- 他の担当がロック中の名刺は出題しない。
- 出題できる名刺が 1 件もない場合、その旨を表示し、対象を再取得する操作と照合結果一覧へ戻る導線を表示する。未照合の名刺がすべて他の担当のロック中である場合も、この状態に含める。
- 自身のロックが自動解除された後に確定操作を行った場合、確定を受け付けず、対象が解放された旨を表示する。
- このとき入力済みの修正入力は破棄しない。画面上に保持したまま、対象を再取得して再度確定できる状態とする。作業 1 件あたりの入力量が多く、破棄すると同じ判断をやり直すことになるため。実現方式は §11 で確定する。

### 7.4 照合の中断

- 修正入力の途中で画面を離れる場合、入力内容がある間は確認ダイアログを表示する（`01_admin_common_ui.md` §8）。
- 確定していない修正入力は保存しない。

### 7.5 応答時間

- 確定操作から次の名刺が表示されるまでの時間は 1 秒以内を目標とする（`05_admin_nonfunctional.md` §2）。

## 8. 現行画面からの引き継ぎ

現行画面（照合結果一覧から遷移）は次を備える。本画面はこれらの機能を引き継ぐ最低線とする。

| 現行の機能 | 本書での扱い |
| --- | --- |
| 項目ごとの値の見比べ | §4.3 |
| 修正入力 | §4.5 |
| 照合ロック（約 200 秒で自動解除） | §4.6 |
| 行ごとの確定チェック | §4.5（2026-08-08 に引き継ぐ方針へ変更） |

現行画面は比較表の右端に行ごとの確定チェックの列を持ち、ヘッダーに全選択のチェックを備える。チェックを入れるとその行の修正入力が読み取り専用になり、外すと再び編集できる。値が一致した行は初期状態でチェック済みとして表示される。

本書は当初この列を引き継がない方針だったが、2026-08-08 の指示により引き継ぐ方針へ変更した。当初挙げた「確認の証跡として機能しない」「保存の可否を制御していない」という問題は、次の形で解消する。

- 確定操作の可否をチェックの状態で制御する。全項目にチェックが付くまで確定できない（§4.5）。チェックが単なる目印ではなく、確定の前提条件になる。
- チェックを外すと修正入力を編集し直せる。一致と判定された項目でも、担当者が誤りに気付けば直せる。判定が誤っていた場合の逃げ道がなかった点を、この操作で埋める。
- 修正入力が空でも、チェックを付ければ「記載なし」として確定できる（§4.5）。値の有無だけを条件にすると、名刺に記載が無い項目を確定できない。

参考: 現行モック `03_admin/reconciliation/detail.html` の比較表は §4.3 の 9 列（項目／OCR 結果／DB 値／入力 1／入力 2／入力 3／修正入力／完成内容／確定）で構成され、本書の内容と同期している。項目は `20_admin_data_input_form.md` §4.4 の作業グループ①〜⑧の全 16 項目を並べ、行の項目名にはどの作業グループに属するかを併記する。

## 10. 画面確認観点

- [ ] サイドバーが表示されず、主要領域が縦スクロールなしで 1 画面に収まる
- [ ] 画面上部に不一致の件数が常に表示され、押すと次の不一致の行へ移動する
- [ ] 画面上部に対象が属するアンケートのアンケート ID とタイトル、納期日時、納期区分が表示される
- [ ] 表と裏の名刺画像が上段に横並びで同時に表示される
- [ ] 1920 × 1080 の表示で比較表に 8 行が収まる
- [ ] 画像の拡大・縮小・回転がキーボードから実行できる
- [ ] 画像のホバー拡大とクリックによる固定・解除が実行できる
- [ ] 各項目について OCR 結果・DB 値・入力 1〜3・修正入力・完成内容・確定が横に並んで表示される
- [ ] 値が存在しない列に「—」が表示される
- [ ] 一致・不一致（修正対象）・確定済みの 3 状態が行単位で識別でき、色を見なくても不一致の併記と確定チェックで判別できる
- [ ] 一致した項目が確定チェックの付いた状態で初期表示され、値が完成内容に採用されている
- [ ] 確定チェックを外すと修正入力欄を編集でき、付け直すと編集できない状態へ戻る
- [ ] 見出し行のチェックで全項目の確定チェックをまとめて切り替えられる
- [ ] 修正入力欄を空のまま確定チェックを付けると、完成内容が「(記載なし)」になる
- [ ] 不一致の項目へ修正入力し、その値が完成内容に採用される
- [ ] 確定チェックが付いていない項目が残っている間、確定操作が非活性になる
- [ ] 確定後、比較表のスクロール位置が先頭へ戻る
- [ ] 初期表示で最初の不一致項目の修正入力欄にフォーカスが当たる
- [ ] 修正入力欄の移動と確定がキーボードのみで完結する
- [ ] 対象が残っていない場合、その旨と照合結果一覧へ戻る導線が表示される
- [ ] 出題できる名刺が 1 件もない場合（全件が他の担当のロック中である場合を含む）、その旨と再取得の操作、照合結果一覧へ戻る導線が表示される
- [ ] 修正入力の途中で画面を離れようとした場合に確認ダイアログが表示される
- [ ] ロックが解除されると名刺画像が伏せられ、再取得の導線が表示される
- [ ] ロックが解除された後の確定試行で、入力内容が失われず対象が解放された旨が表示される
- [ ] Lv2 でログインした場合、画面上部に会社名が表示されない
- [ ] Lv2 でログインした場合、他グループの名刺が出題されない
- [ ] Lv1 でログインした場合、本画面へアクセスできない

## 11. 画面外の確認事項

| # | 項目 | 内容 |
| --- | --- | --- |
| 1 | DB 値の由来 | 並列表示する「DB 値」が何を指すかを確定する。過去に確定した同一人物のデータか、回答時に取得した値かで、照合時の扱いが変わる。 |
| 2 | 一致・不一致の判定条件 | 何をもって一致とみなすかを確定する。入力 1〜3 の全一致か、多数決か、OCR 結果を含めるかで不一致件数が変わる。入力の確定条件（`20_admin_data_input_form.md` §11 の #2）、照合結果一覧の完了件数（`21_admin_matching_list.md` §11 の #5）、オペレーター実績確認の正答率の分母（`24_admin_achievements.md` §11 の #1・#2）と併せて、本項を含む 4 点を同一の定義で確定する。定義が割れると、同じ作業に対して画面ごとに異なる件数が表示される。 |
| 3 | 入力が 3 件に満たない場合 | 入力 1〜3 のうち一部しか存在しない状態で照合対象となるかを確定する。 |
| 4 | ロックの自動解除時間 | モックは 3 分（180 秒）を暫定値としている。現行の約 200 秒と 3 分のどちらを正式値とするかを確定する。作業 1 件あたりの所要時間を基準に判断する。入力画面（`20_admin_data_input_form.md` §4.7）と同じ値を用いる。 |
