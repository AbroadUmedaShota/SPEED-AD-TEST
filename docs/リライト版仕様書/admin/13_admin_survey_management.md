## 1. 文書目的

- 本書は、アンケート管理（全顧客のアンケートの横断管理）の要件を定義する。
- 全画面に共通する権限、UI 規則、監査ログ、通知、用語は共通編を参照する。本書は本画面に固有の要件を扱う。
- アンケート 1 件ごとの設定変更と要注意操作は本書の対象外とし、`14_admin_survey_detail.md` で扱う。

## 2. 画面概要

- 全顧客のアンケートを横断で検索し、状態を確認する画面。
- 利用者側で制限されている操作（会期中の編集、強制停止）を運営権限で実行する入口となる。
- 会期後は、名刺データ化の結果を確認する。
- 「今日動いている案件」と「新しく増えた案件」を把握し、対応が必要なアンケートへ移動する。

### 2.1 一覧と詳細の責務分担

| 画面 | 担当する操作 |
| --- | --- |
| アンケート管理（本画面） | 横断検索、状態の確認、作成・削除、関連データのダウンロード、詳細・請求・アカウントへの遷移 |
| アンケート詳細（SCR-A-005） | 個別アンケートの全設定の確認・変更、公開後の変更などの要注意操作 |

## 3. 想定利用者と対象範囲

### 3.1 想定利用者

- 運営全体を管理する Lv3・Lv4。顧客からの依頼に応じた代行操作、案件の進行状況の確認、納品データの確認を行う。

### 3.2 対象範囲

- アンケートの一覧・検索
- アンケートの作成・編集・削除（会期前から会期中）
- 利用者側で制限されている操作の実行
- 名刺データ化データの確認（会期後）
- 関連データのダウンロード（通期）
- データ化申込プランの確認
- お礼メールの内容確認
- 請求情報・アカウント情報・アンケート詳細への遷移

### 3.3 対象外

- 個別アンケートの全設定の変更と公開後の変更（`14_admin_survey_detail.md`）
- 名刺データの入力・照合作業（`19_admin_data_input_list.md`、`21_admin_matching_list.md`）
- 請求金額の確認（`15_admin_billing.md`）

## 4. 画面要件

本節の任意要件は 2 分類で扱う。§4.9「追加要件（あったほうが良い）」はたたき台 E 列由来で導入を前提とする追加、§4.10「検討中の要件」はたたき台 H 列由来で採否が未定のものとする（`README.md` 書き方の方針）。

### 4.1 共通構成

- ヘッダー、サイドバー、パンくずを表示する（`01_admin_common_ui.md` §2）。
- 画面タイトルを表示する。
- 画面は上から、検索・絞り込み条件、アンケート一覧の順に配置する。
- 一覧の上部に、アンケートの作成の操作を配置する。

### 4.2 一覧表示

各アンケートについて次を表示する。

| 表示項目 | 内容 |
| --- | --- |
| アンケート ID | アンケートを一意に識別する ID |
| タイトル | アンケートのタイトル |
| ユーザー ID | 作成した利用者の ID |
| 会社名 | 作成した利用者の所属会社 |
| 会期 | 回答受付期間の開始日と終了日 |
| 作業ステータス | 名刺データ化の進み具合を表す区分 |
| 有効回答数 | 回答に名刺画像がついた有効回答の件数。見出しまたは各セルにマウスオーバーすると、実際のアンケート回答数と有効回答数が異なる場合があること、および両方の件数を確認できる |
| データ化申込プラン | 名刺データ化の申込内容と納期区分 |
| 納期日 | 名刺データ化の納期日。終了が近い案件の把握と並び替えに使う。会期前は納期日が未確定のため表示しない。データ化完了後も保持して表示する（2026-08-18 確定） |
| データ化件数 | 名刺データ化を実施した件数（現行画面の「実際の件数」）。会期前〜会期中は未発生のため「—」 |
| データ化完了予定日 | 名刺データ化の完了予定日。作業ステータスに付記して表示する（現行画面の表示項目） |

- 一覧はページングと表示件数の選択に対応する（`01_admin_common_ui.md` §4.3）。本画面の既定表示件数は 50 件とし、表示件数の選択肢も 50 件とする。
- 各列で昇順・降順の並び替えができる。
- 有効回答数の集計範囲（テスト回答を含むか、名刺画像付きとみなす条件）は §11 で確定する。
- 各行から対象の実アンケート画面（回答画面）を新しいタブで開く導線を置く（現行画面の「開く」を引き継ぐ）。
- 行を押下するとアンケート詳細（SCR-A-005）へ遷移する。行内の操作は行の押下と分離する（`01_admin_common_ui.md` §4.5）。

### 4.3 検索・絞り込み

| 条件 | 種別 | 内容 |
| --- | --- | --- |
| アンケート ID | 検索 | 完全一致または前方一致で対象を絞り込む |
| ユーザー ID | 検索 | 完全一致または前方一致で絞り込む |
| 会社名 | 検索 | 部分一致で絞り込む |
| 氏名 | 検索 | 部分一致で絞り込む |
| 作業ステータス | 絞り込み | 作業ステータスの値から選択する。初期値は「すべて」 |

- 条件をまとめて初期状態へ戻す操作を用意する。
- 他画面から遷移した場合は、遷移元が指定した条件で絞り込んだ状態で開く（`01_admin_common_ui.md` §4.1.1）。上表の条件に加えて、納期区分を遷移時の絞り込み条件として受け取る。
- 作業ステータスの値集合は画面間で一致していない。正とする値集合は `04_admin_common_glossary.md` §6.2 で確定する。

### 4.4 アンケートの作成・編集・削除

| 操作 | 実行できる期間 | 内容 |
| --- | --- | --- |
| 作成 | — | 運営側でアンケートを新規作成する |
| 編集 | 会期前から会期中 | アンケートの内容を変更する。変更はアンケート詳細（SCR-A-005）で行い、一覧の行の押下で遷移する（2026-08-18: 行押下と重複していた行操作「詳細」は廃止） |
| 削除 | 会期前から会期中 | アンケートを削除する |

- 削除は確認ダイアログを表示し、対象のアンケート ID とタイトルを明示する（`01_admin_common_ui.md` §7.1）。
- 削除は監査ログの記録対象とする（`02_admin_common_audit_log.md` §3）。
- 運営側による作成の可否と削除の方式は §11 で確定する。

### 4.5 制限操作の実行

- 利用者側で制限されている操作を、運営権限で実行する。会期中の編集がこれに該当する。
- 実行時は確認ダイアログを表示し、対象と操作内容を明示する。
- 公開後の設問変更と個別回答の削除は、アンケート詳細（SCR-A-005）で行う。本画面では実行しない。

### 4.6 データ化データの確認

- 会期後、名刺データ化の結果を確認する。確認の手段は §4.7 の関連データのダウンロードとする。データ化完了かどうかは作業ステータス列で判断する。
- 完成データの利用者側への反映は、照合の完了を契機とする。現行実装がこの動きになっているかは開発側へ現状の開示を要求中である（§11 の #5）。

### 4.7 関連データのダウンロード

- 会期の前後を問わず、アンケートに紐づくデータをダウンロードできる。
- 対象は回答データと名刺画像とする。ダウンロード操作のモーダルでは完成データ CSV・全レコード CSV・名刺画像（ZIP）を選択する。
- 行の操作は「データ DL」1 つとし、データ化の完了・未完了でラベルを変えない。モーダルの中身も行の状態によって変えない（`01_admin_common_ui.md` §4.6）。
- ダウンロードの出力形式と文字コードは `01_admin_common_ui.md` §10 に従う。
- ダウンロードは監査ログの記録対象（データ持ち出し）とする（`02_admin_common_audit_log.md` §3）。

### 4.8 データ化申込プランとお礼メールの確認

- アンケートごとの申込プラン（納期区分）は一覧（§4.2）で確認できる。
- お礼メールの内容の確認と、請求情報・アカウント情報への遷移は、アンケート詳細（SCR-A-005）で行う。一覧の行操作は 詳細・削除・データ DL に限定し、行内の導線集中を避ける。

### 4.9 追加要件（あったほうが良い）

| 要件 | 内容 |
| --- | --- |
| 当日会期・新着の確認 | 当日に会期を持つアンケートと、前日比で増えたアンケートを識別できるように表示する |
| 強制停止 | トラブル発生時に、会期中のアンケートの回答受付を運営側で停止する。実行はアンケート詳細（SCR-A-005）の要注意操作から行う |
| 完了データの手動アップロード | 完成データをファイルから直接取り込み、アンケートへ反映する。実行はアンケート詳細（SCR-A-005）の要注意操作から行う |

完了データの手動アップロードは、通常フローが機能しない場合の代替手段として位置づける。通常は照合の完了によって完成データが反映される。過去に表計算ソフトへ直接入力して納品を継続した経緯があり、その代替手段を画面上の操作として持つ。

### 4.10 検討中の要件

| 要件 | 内容 |
| --- | --- |
| 回答データのエクスポート | 回答データを CSV 等の形式で出力する |

## 5. 通知

本画面の操作を起点とする通知・メールの発火はない（`03_admin_common_notifications.md` §2）。確認依頼メールはアンケート詳細（SCR-A-005）から送信する。

## 6. 権限とデータ範囲

| 権限レベル | 扱い |
| --- | --- |
| Lv1 | 本画面へアクセスできない。サイドバーに項目を表示しない |
| Lv2 | 本画面へアクセスできない。サイドバーに項目を表示しない |
| Lv3 | 全範囲のアンケートを表示・操作できる |
| Lv4 | 全範囲のアンケートを表示・操作できる |

- 本画面は顧客情報を扱うため、Lv2 以下はテナント分離により到達しない（`00_admin_common_permissions.md` §3）。
- 権限判定はサーバー側で行う（`00_admin_common_permissions.md` §9.1）。

## 7. 状態と挙動

### 7.1 初期表示

- 検索条件は未入力、作業ステータスの絞り込みは「すべて」の状態で表示する。
- 一覧の既定の並び順は会期の開始日の降順とする。
- 表示件数の既定は 50 件とする。

### 7.2 会期による操作の可否

- 会期前から会期中は、編集と削除を実行できる。
- 会期後は、データ化データの確認を実行できる。
- 会期の状態によって実行できない操作は、操作要素を表示しない。

### 7.3 詳細からの復帰

- アンケート詳細から戻った場合、直前の検索条件・絞り込み条件・ページ位置を保持した状態で一覧を再表示する。

### 7.4 操作の記録

次の操作は監査ログに記録する（`02_admin_common_audit_log.md` §3）。

- アンケートの削除
- 制限操作の実行（代行変更）
- 完了データの手動アップロード
- 回答データ・名刺画像のダウンロード

## 8. 現行画面からの引き継ぎ

現行画面 `/admin/surveys` は次を備える。本画面はこれらの機能を引き継ぐ最低線とする。

| 現行の機能 | 本書での扱い |
| --- | --- |
| 一覧表示 | §4.2 |
| 検索・絞り込み | §4.3 |
| 編集 | §4.4。行の「編集」押下は同一画面へ戻る状態であり、遷移先をアンケート詳細（SCR-A-005）とする |
| 削除 | §4.4 |
| アンケートを開く | §4.2（行の「開く」導線） |
| 名刺画像のダウンロード | §4.7 |
| 完了 CSV のアップロード | §4.9 |
| 請求情報・アカウント情報への遷移 | §9 |

現行画面の作業ステータスの絞り込みは、作成中 / 会期中 / データ化中 / アップ待ち / アップ完了 / データ化なし の 6 値である。照合結果一覧（`21_admin_matching_list.md`）の現行値集合とは先頭の値が異なる。値集合の確定は `04_admin_common_glossary.md` §6.2 で扱う。

参考: 現行モック `03_admin/survey-management.html` は本書の内容と同期している（行操作 詳細・実アンケート画面を開く・削除(会期前〜会期中のみ)・データ DL、公開の手動操作なし）。

## 10. 画面確認観点

モックアップ上で次を確認する。

- [ ] アンケート ID・ユーザー ID・会社名・氏名による検索が機能する
- [ ] 作業ステータスによる絞り込みが機能する
- [ ] 条件をまとめて初期状態へ戻す操作が機能する
- [ ] 一覧から対象を選択するとアンケート詳細へ遷移する
- [ ] 会期前から会期中のアンケートで編集・削除の操作要素が表示される
- [ ] 会期後のアンケートで編集・削除の操作要素が表示されない
- [ ] 削除時に確認ダイアログが表示され、対象のアンケート ID とタイトルが明示される
- [ ] 回答データと名刺画像のダウンロード操作を実行できる
- [ ] データ化申込プランが一覧に表示される
- [ ] 行の操作が 実アンケート画面を開く・削除（会期前〜会期中）・データ DL で構成され、データ DL のラベルが行の状態で変わらない
- [ ] 一覧にデータ化件数と完了予定日が表示され、行から実アンケート画面を開く導線がある
- [ ] Lv2 以下でログインした場合、本画面の URL へ直接アクセスしても表示されない

## 11. 画面外の確認事項

| # | 項目 | 内容 |
| --- | --- | --- |
| 1 | 運営側による作成の可否 | 運営がアンケートを新規作成できるようにするかを確定する。作成する場合、作成者として記録する利用者をどう指定するかを決める。 |
| 2 | 削除の方式 | 論理削除と物理削除のいずれとするかを確定する。紐づく回答・名刺画像・請求への波及も併せて決める。名刺データ化が進行中のアンケートを削除した場合に、入力キューへの出題と照合ロックをどう扱うかを含める。 |
| 3 | 作業ステータスの値集合 | 現行画面の 6 値（作成中始まり）、照合結果一覧の 6 値（会期前始まり）、たたき台の 4 値を突き合わせ、正とする値集合を確定する。 |
| 4 | 有効回答数の集計範囲 | 一覧に表示する有効回答数にテスト回答を含めるか、名刺画像付きとみなす条件、会期前に送信された回答の扱いを確定する。 |
| 5 | 完成データの自動反映 | 照合完了後に完成データが利用者側へ自動反映されるかは、開発側へ現状の開示を要求中である。本書は照合完了を反映の契機とする前提で記述しており、開示結果により §4.6 を見直す。`21_admin_matching_list.md` §11 の #11、`22_admin_matching_form.md` §11 の #9 と同一の論点であり、3 点を同時に確定する。 |
| 6 | 手動アップロードの適用条件 | 完了データの手動アップロードを実行できる条件（作業ステータス、既存データの有無）と、上書き時の扱いを確定する。 |
| 7 | 強制停止の挙動 | 強制停止した際に、回答受付を停止するのみか、既存の回答も無効化するかを確定する。停止後に再開できるかも決める。停止時点で入力キューに残っている名刺と、照合ロック中の名刺の扱いを併せて決める。 |
| 8 | 新着の判定基準 | 「新しく増えた案件」の判定を前日比とするか、未確認フラグで管理するかを確定する。 |
| 9 | エクスポートの出力項目 | 回答データのエクスポートを導入する場合、出力する列と名刺データ化結果を含めるかを確定する。 |
