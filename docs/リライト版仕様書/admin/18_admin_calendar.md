# 営業日カレンダー 要件定義書

## 1. 文書目的

- 本書は、営業日カレンダーの要件を定義する。
- 全画面に共通する権限、UI 規則、監査ログ、通知、用語は共通編を参照する。本書は本画面に固有の要件を扱う。
- 納期日時そのものの表示と照合作業の進捗は本書の対象外とし、`21_admin_matching_list.md` で扱う。

## 2. 画面概要

- 納期計算の前提となる休業日と振替営業日を運営側で管理する画面。
- あわせて、Lv2 が案件量と人員を見比べて作業をアサインする運用画面として機能する。
- 月単位のカレンダーを中心に構成し、日付ごとの営業日設定、その日に会期を持つアンケート、作業のアサイン状況を扱う。
- 表示範囲と操作範囲はログイン中アカウントのデータ範囲と権限に従う（§6）。

### 2.1 タブ構成（2026-08-14 追加）

本画面は 2 つのタブで構成する。

| タブ | 担当する目的 | 主な利用者 |
| --- | --- | --- |
| 営業日（既定） | 休業日・振替営業日・定休日を設定する | Lv3・Lv4（設定）／Lv2（参照） |
| アサイン | 案件量と人員の過不足を見て、作業をアサインする | Lv2（自グループ）／Lv3・Lv4（全グループ） |

タブを分ける理由は次のとおり。

- 会期の帯と作業期間の帯を同じカレンダーに重ねると、1 週あたり最大 10 本の帯が積まれ、1 週に並べられる上限（§4.4）を超えて省略が発生する。
- 休業日の設定と作業のアサインは判断の材料が違う。休業日を足して動くのは納期であって会期ではないため、休業日を決める場に会期を並べても判断材料にならない。
- 休業日の設定（Lv3・Lv4）と作業のアサイン（Lv2）は、利用者も操作頻度も異なる。

次の要素はタブによらず常に表示する。休業日はどちらの目的でも前提となるためである。

- 営業日区分（営業日・休業日・振替営業日）の日付単位の表示
- 対象月の移動操作と当日への復帰操作
- 選択中の日付

タブは URL から直接指定できるものとし、他画面からアサインタブへ遷移できるようにする。

### 2.2 アサインの責務分担

| 画面 | 担当する範囲 |
| --- | --- |
| 営業日カレンダー アサインタブ（本画面） | アサインの実行。アンケートと会社の組み合わせで投入人数を決め、案件量と処理能力の過不足を判断する |
| データ入力対象一覧（SCR-A-009） | 作業の実施。作業可能件数の確認と入力画面への遷移 |

アサイン結果をデータ入力対象一覧へどう反映するかは §7.3 で扱う。

### 2.3 提供の段階（2026-08-14 追加）

タブ単位で段階的に提供する。

| 段階 | 範囲 | 前提 |
| --- | --- | --- |
| 第 1 段階 | 営業日タブ | §11 のうち #1・#2・#6・#8・#12・#13 を確定する |
| 第 2 段階 | アサインタブ | §11 のうち #5・#7・#9・#14・#15・#16 を確定する |

現行画面 `/admin/calendar` は定休日設定と個別休業日設定のみを備える（§8）。アサインは現行画面に存在しないため、第 2 段階まで提供されない間も現行の運用は維持される。

## 3. 想定利用者と対象範囲

### 3.1 想定利用者

- 作業をアサインする Lv2（OperatorAdmin）。案件量と人員のバランスを見て、日ごとの作業割当を決める。
- 営業日を管理する Lv3・Lv4。休業日・振替営業日を設定し、納期計算の前提を維持する。

### 3.2 対象範囲

- 休業日・振替営業日の設定と変更
- 定休日（曜日単位）の設定
- 月次カレンダー上でのアンケート表示
- 作業のアサインとキャパシティの調整

### 3.3 対象外

- 納期日時の算出ロジック
- 入力・照合の作業進捗（`19_admin_data_input_list.md`、`21_admin_matching_list.md`）
- オペレーターの登録・権限設定（`23_admin_operator_management.md`）

## 4. 画面要件

### 4.1 共通構成

- ヘッダー、サイドバー、パンくずを表示する（`01_admin_common_ui.md` §2）。
- 画面タイトルを表示する。
- 画面タイトルの下にタブを配置する（§2.1）。選択中のタブは他と区別して示し、いずれか 1 つが常に選択された状態とする。
- カレンダーを中心に配置し、前月・翌月へ移動する操作と、当月かつ当日へ戻る操作を用意する。この操作はタブによらず共通とする。
- 操作ボタンはタブに応じて出し分ける。営業日タブでは定休日設定・休業日CSV取込・休業日と振替営業日の追加を、アサインタブでは処理能力の設定を配置する。

#### 4.1.1 表示モード（2026-08-14 改訂）

表示モードはタブごとに用意する。

| タブ | モード | 表示範囲 |
| --- | --- | --- |
| 営業日 | 単月（既定） | 対象月の週を表示する |
| 営業日 | 年間 | 月×指標の一覧表（§4.2.1）。日別のカレンダーは表示しない |
| アサイン | 前後2週（既定） | 対象月の前 2 週から後 2 週までを上下に並べて表示する。月が替わる位置に月名の区切り行を挟み、対象月以外の日付は淡色で示す |
| アサイン | 単月 | 対象月の週を表示する |

- 営業日タブの既定を単月とするのは、会期が月をまたぐことが少なく、対象月の週だけで足りるためである。アサインタブの既定を前後2週とするのは、作業期間が会期終了日の翌営業日から最大 6 営業日ぶん伸び、月末をまたぐためである。
- タブを切り替えたとき、切り替え先でも使えるモードであればそのモードを保つ。使えない場合は切り替え先の既定モードにする。
- 画面を開いた直後は、そのタブの既定モードから始める。

### 4.2 カレンダー表示

- 1 日を 1 マスとして日付順に配置する。表示範囲は §4.1.1 の表示モードに従う。
- 各日付には、タブによらず次を表示する。

| 表示項目 | 内容 |
| --- | --- |
| 日付 | 年月日 |
| 営業日区分 | 営業日、休業日、振替営業日のいずれか |

- タブごとに、上記へ次を加える。

| タブ | 追加する表示項目 | 内容 |
| --- | --- | --- |
| アサイン | 作業期間の帯 | その日にデータ化作業があるアンケートと、その充足状態 |
| アサイン | 必要枚数・供給枚数 | その日に作業があるアンケートを通した 1 日あたりの合計 |
| アサイン | 不足アンケート数 | その日に作業があるアンケートのうち供給が必要量に届いていない件数 |

- 枚数・人数は数値で表示する。図やグラフは用いない。
- 日付を選択すると、日付詳細領域にその日の対象アンケートを表示する（§4.4、§4.5）。
- 選択中の日付は、営業日区分の表示とは別に、選択状態としてカレンダー上で識別できるようにする。
- カレンダーには、休業日・振替営業日・選択中の各状態を示す凡例を添える。凡例に並べる帯の種類はタブに応じて変える。
- 月セルの表示方式は §4.4 で確定する。

#### 4.2.1 年間ビュー（2026-08-12 追加・2026-08-14 改訂）

- 年間モードでは、月×指標の一覧表を表示する。図やグラフは用いない。
- 年間モードは営業日タブに置く。年間の粒度で見るのは営業日の姿であり、日ごとの人員配分は月の粒度で扱うためである。
- 各月の行に、営業日数・休業/振替の個別設定数・会期のあるアンケート件数を表示する。
- 営業日数は定休日・祝日・個別設定を反映した日数とする。会期のあるアンケート件数は、その月に会期がかかるアンケートの件数とする。
- 月の行を選択すると、単月モードでその月を表示する。
- 年間モードでは日付単位の道具（月の集計行・日付詳細領域）は表示しない。

#### 4.2.2 月の集計行（2026-08-14 追加）

カレンダーの上に、対象月の集計を 1 行で表示する。内容はタブごとに変える。

| タブ | 集計項目 |
| --- | --- |
| 営業日 | 営業日数、休業日数、個別設定の件数、会期のあるアンケートの件数 |
| アサイン | アンケートの充足状態の内訳（未アサイン・不足（深刻）・不足・充足・人数過多・終了）、全社を総動員しても不足するアンケートの件数、要員が重複している日数 |

- 「全社を総動員しても不足」は独立した状態ではなく、未アサイン・不足に付く印である。内訳であることが読み取れる表記とし、他の件数と足し合わせられないようにする。
- アサインタブの集計行には、カレンダーの表示を絞る操作を併置する（2026-08-14 追加）。

| 操作 | 内容 |
| --- | --- |
| 不足のみ表示 | 未アサイン・不足（深刻）・不足のアンケートだけをカレンダーに残す |
| 終了を隠す | データ化が完了したアンケートをカレンダーから外す。集計行の件数には残す |

#### 4.2.3 狭い画面での行形式（2026-08-14 追加）

本画面の基準は PC 表示とする。画面幅が狭い環境では、1 日 1 マスの 7 列構成に必要な列幅を確保できないため、**1 日 1 行の縦並び**へ切り替える。

- 行の左に日付と曜日を置き、右にその日にかかるアンケートを縦に並べる。
- 営業日区分は行の背景で示す。休業日・振替営業日の区別は 7 列構成と同じ扱いとする。
- 帯は日をまたぐ表現であるため行形式では持たない。アサインタブでは、同じアンケートが複数日にかかる場合に該当する各日の行へ並べる。営業日タブは 7 列構成と同じくアンケートを並べず、日付・営業日区分と会期の件数（§4.4.1）だけの行とする。
- 行形式では対象月の日付のみを並べる。
- 日付を選択する操作と、アンケートを選択する操作は行内で分ける。
- 日付詳細領域はカレンダーの下へ積む。
- 曜日の見出し行は 7 列構成のためのものなので、行形式では表示しない。
- 幅が切り替わる境目をまたいだ場合は、その時点の幅に応じた形式で描き直す。
- 切り替える幅の値は実画面のレビューで確定する（※要確定・§11 の #17）。

### 4.3 営業日の設定

| 設定 | 内容 |
| --- | --- |
| 定休日 | 曜日単位で休業日とする設定。土曜・日曜・祝日をそれぞれ指定する |
| 個別休業日 | 日付を指定して休業日とする設定 |
| 振替営業日 | 定休日にあたる日付を、営業日として扱う設定 |

- 設定の変更は Lv3 以上が行う（§6）。
- 個別休業日と振替営業日には、設定の理由をメモとして記録できる。
- 登録済みの個別設定は編集できる。日付・区分・メモのいずれも変更でき、削除してからの再登録を求めない。編集で日付を移す場合、移動先に既存の個別設定があるときはエラーを表示し、保存しない（2026-08-14 追加）。
- 設定を削除する場合は確認ダイアログを表示する（`01_admin_common_ui.md` §7.1）。
- 定休日・個別休業日・振替営業日の追加・変更・削除、および CSV による一括取込は監査ログへ記録する（`02_admin_common_audit_log.md` §3・2026-08-14 追加）。納期の算出前提を変える操作であるため、実行者と対象日を追跡できるようにする。

#### 4.3.2 CSV 出力（2026-08-14 追加）

表示中の月の営業日区分を CSV として出力する。

| 列 | 内容 |
| --- | --- |
| date | 日付 |
| day_of_week | 曜日 |
| status | `BUSINESS_DAY` / `HOLIDAY` / `SUBSTITUTE_WORKDAY` |
| status_label | 営業日 / 休業日 / 振替営業日 |
| source | `REGULAR`（定休日）/ `PUBLIC_HOLIDAY`（祝日）/ `INDIVIDUAL`（個別設定）。営業日は空 |
| reason | 祝日名、または定休日の曜日 |
| memo | 個別設定に記録したメモ |

- 出力は営業日を含む月の全日を対象とする。取込（§4.6）が個別設定だけを扱うのに対し、出力は月の姿をそのまま書き出す。
- 休業日がどの設定で決まったかは日付だけでは追えないため、由来を `source` として持たせる。
- 形式は `01_admin_common_ui.md` §10 のファイル出力に従う。
- 出力操作は監査ログの「データ持ち出し」として記録する（`02_admin_common_audit_log.md` §3）。

同一の日付に複数の設定が及ぶ場合、次の規則で解決する。規則の全体は確定前とする（※要確定・§11 の #12）。

- 個別設定（個別休業日・振替営業日）を定休日・祝日より優先する。定休日・祝日と重なる日付では、個別設定の内容をカレンダー表示と納期計算に用いる。
- 同一の日付に個別休業日と振替営業日を重複して設定することはできない。重複する設定を保存しようとした場合はエラーを表示し、保存しない。

#### 4.3.1 納期への影響の提示（2026-08-14 追加）

営業日設定を変更すると、作業期間と納期が後ろまたは前へずれる（§4.5.1）。営業日タブには作業期間を表示しないため、変更した本人が影響を読み取れるようにする。

- 定休日・個別休業日・振替営業日を追加または削除した直後に、納期が変わったアンケートを一覧で示す。
- 一覧にはアンケート ID、タイトル、変更前の納期、変更後の納期、ずれた向きを含める。アンケート詳細へ遷移できるようにする。
- データ化が完了しているアンケートは対象に含めない。納期が動いても実務上の影響がないためである。
- 一覧は利用者が閉じるまで残す。一定時間で消える通知にしない。変更の直後に見落とすと、影響を後から確認する手段がなくなるためである。
- 件数が多い場合は先頭の数件を表示し、残りは件数で示す。表示する件数は実画面のレビューで確定する（※要確定・§11 の #17）。
- 納期が変わったアンケートがない場合は表示しない。

### 4.4 アンケート表示

アサインタブの月セルには、アンケートを **帯** として表示する。帯は横につなぎ、週をまたぐ場合は継続を示す記号を端に置く。営業日タブは帯を持たない。

#### 4.4.1 営業日タブ（2026-08-17 改訂）

- 月セルには帯を表示しない。休業日・振替営業日の設定に集中させる。
- 会期の帯を並べていたが、休業日を足して動くのは納期であって会期ではないため、設定の判断材料になっていなかった。加えて、アサインタブと同じ形のカレンダーでありながら出てくるアンケートが違い（会期のアンケートと作業のアンケート）、見比べたときに誤解を招いていた。
- 休業日を変えたときの影響は §4.3.1 の納期への影響の提示で扱う。
- 月セルには、その日に会期を持つアンケートの件数を **「会期 N 件」** として表示する。0 件の日には表示しない。補足表示にアンケート ID とタイトルを並べる。
- 件数だけを置き、アンケート名は月セルに出さない。休業日の設定を読むのを妨げない粒度に留め、内訳は日付を選んで日付詳細領域で読む。
- 帯があふれたことを示す「他 N 件」は営業日タブでは表示しない。営業日タブは帯を持たないため隠れているものが無く、表示すると会期の件数の横に別の数が並んで会期が増えたように読める。
- 件数が無いと、月の集計行が会期のあるアンケート数を示しているのに、どの日を選べば辿り着くかが画面から読めない。表示中の月で会期を持つ日は全体の一部（デモデータでは 31 日中 20 日）であり、日付を総当たりすることになる。
- 会期の内訳は日付詳細領域で読む。件数は月セル・月の集計行（§4.2.2）・年間ビュー（§4.2.1）で確認する。
- 日付詳細領域には、その日に会期を持つアンケートを並べ、アンケートごとに次を表示する。

| 表示項目 |
| --- |
| アンケート ID、タイトル |
| 会期（日付のみ。時刻は表示しない。ユーザー側のデータが会期に時刻を持たないため — 2026-08-06 決定） |
| 納期区分、納期 |
| ステータス、回答件数 |

#### 4.4.2 アサインタブ（2026-08-17 改訂）

- 帯は **§4.5.1 で算出する作業日の初日から納期まで** の 1 本とする。1 件のアンケートに対して帯は 1 本である。
- 帯にはアンケート ID・タイトル・必要枚数・供給枚数を表示し、充足状態の色を付ける。
- 会期は帯として表示しない。誰をいつ入れるかは作業期間だけで判断でき、会期は営業日タブ（§4.4.1）と日付詳細領域で確認できる。
- 納期区分がオンデマンドのアンケートは会期中にデータ化するため、作業日が会期の各日と一致する。この場合の帯が会期をそのまま表す。
- 日付詳細領域には、その日に作業があるアンケートを先に、会期だけのアンケートを後に並べる。アンケートごとにアンケート ID、タイトル、会期、納期区分、納期、作業期間とアサイン状況を表示する。

会期を帯として併記した場合、同じ形が 2 つ並んで 1 件のアンケートが 2 件に見える。形を変えて細い線にすると、文字を持てないため罫線と見分けが付かず、どのアンケートのものかも読めない。会期を表示しないことで、1 本の帯が 1 件のアンケートに対応する。

1 週あたりに確保する段は、描く区間と一致させる。表示しない区間まで段を押さえると、帯の無い位置が他のアンケートを下へ押し出す。

#### 4.4.3 共通

- 1 週に並べる帯には上限を設け、あふれた件数は月セルの下部に「他 N 件」として示す。
- 帯からあふれた場合の省略表示は、補足表示で全文を読めるようにする。
- 日付詳細領域に収まらない件数がある場合は、領域内の縦スクロールで全件を確認できるようにする。
- 表示対象はログイン中アカウントのデータ範囲に限定する。

日付詳細領域のアンケートごとに、作業画面への遷移導線を配置する。

| 遷移先 | 表示条件 | 引き継ぐ内容 |
| --- | --- | --- |
| アンケート詳細（SCR-A-005） | 常に表示する | 対象アンケート |
| データ入力対象一覧（SCR-A-009） | 対象アンケートに名刺データ化の対象が存在する場合に表示する | なし（2026-08-14 改訂） |
| 照合結果一覧（SCR-A-011 / SCR-A-012） | 対象アンケートに名刺データ化の対象が存在する場合に表示する | 対象アンケート |

- 引き継いだアンケートは、遷移先の絞り込み条件へ適用した状態で表示する。
- データ入力対象一覧は項目グループ単位の全体キューを扱う画面であり、アンケート単位の絞り込みを持たない。このため対象アンケートを引き継げない。遷移先での絞り込みを可能にするかは、アサイン結果の反映方式と同じ論点として確定する（※要確定・§11 の #9）。導線には、絞り込みが効かないことを補足表示で示す。

### 4.5 アサイン

- アンケートと会社の組み合わせで、投入する人数をアサインする。誰を出すかは各社が社内で決めるため、本画面では会社と人数までを扱い、個人は指定しない。
- 人数は会期の全日ではなく、§4.5.1 の作業期間を通した 1 日あたりの人数とする。
- アサインを確定すると、担当会社のオペレーター管理者（Lv2）へ割当通知を送信する（§5）。
- 人数を 0 にすることでアサインを取り消せる。

#### 4.5.1 作業期間と必要人員の算出

作業期間は納期区分から算出する。納期の起算は会期終了日の翌営業日を 1 営業日目とし、営業日の判定には §4.3 の営業日設定（定休日・個別休業日・振替営業日）を用いる。休業日を追加すると納期と作業期間が後ろへずれる。

| 納期区分 | 納期 | 作業期間 |
| --- | --- | --- |
| オンデマンド | 当日中 | 会期の各日 |
| 超特急 | 1 営業日 | 会期終了日の翌営業日から 1 営業日 |
| 特急 | 3 営業日 | 会期終了日の翌営業日から 3 営業日 |
| 通常 | 6 営業日 | 会期終了日の翌営業日から 6 営業日 |
| お試し | 6 営業日 | 会期終了日の翌営業日から 6 営業日 |

納期区分ごとの営業日数と起算の規則は利用者側の定義と一致させる（`04_admin_common_glossary.md` §4）。

充足の判定は人数ではなく処理枚数で行う。会社ごとに 1 人 1 日あたりの処理枚数が異なるため、同じ人数でも処理できる量が変わるためである。

```text
1 日あたり必要枚数 = 見込み枚数 ÷ 作業期間の営業日数
1 日あたり供給枚数 = Σ 会社ごと（投入人数 × その会社の 1 人 1 日あたり処理枚数）
充足率              = 供給枚数 ÷ 必要枚数
```

充足率で次の段階に分けて表示する（2026-08-12 追加）。安全バッファは持たず素の 100% で判定する。段階の閾値は暫定値とし、実画面のレビューで調整する（※要確定・§11 の #16）。

| 状態 | 条件 |
| --- | --- |
| 未アサイン | 供給枚数が 0 |
| 不足（深刻） | 充足率 70% 未満。このままでは処理できない水準 |
| 不足 | 充足率 70% 以上 100% 未満 |
| 充足 | 充足率 100% 以上 130% 以下 |
| 人数過多 | 充足率 130% 超。余剰の枚数と平均換算の人数を示し、他アンケートへ回せることを伝える |

- 見込み枚数は利用者側の名刺データ化設定で入力された想定件数を用いる（アンケート回答 1 件＝名刺 1 枚）。
- 人数は平均的な生産性から換算した目安として併記する。人数が目安に達していても担当会社の処理能力では届かない場合があるため、その旨を示す。
- 日単位の不足は、アンケートごとの不足分の合計で数える。会社が異なれば供給を融通できないため、その日の合計が足りていてもアンケート単位では不足しうる。

#### 4.5.2 会社ごとの処理能力

処理能力は「1 人あたりどれだけ処理できるか」と「何人出せるか」の 2 つに分け、取得元を変える。

| 要素 | 取得元 | 理由 |
| --- | --- | --- |
| 1 人 1 日あたりの処理枚数 | オペレーター実績確認（SCR-A-015）の当月の作業件数 ÷ 当月の営業日数 ÷ 対象人数 | 生産性は過去の実測から推定する |
| 同時に出せる人数の上限 | オペレーター管理（SCR-A-014）で状態が有効なアカウント数 | 実績から人数を導くと、退職・無効化された人の過去実績を現在の戦力として数えてしまう |

無効・招待中のアカウントは稼働可能な人数に数えない。稼働可能なアカウントが 0 名の会社へは人数を入力できないようにし、増員依頼の宛先としても既定では選択しない。

同じ人員を複数のアンケートへ重複して配員できないようにする。上限はアンケートごとではなく、作業日をまたいで判定する。

```text
そのアンケートが確保できる人数 = 稼働可能なアカウント数 − 作業日が重なる他アンケートでの使用人数の最大値
```

作業日のうち他アンケートの使用が最も多い日を基準とする。入力欄はこの人数を上限とし、確定時にも同じ上限で頭打ちにする。上限を差し引いた理由（どの程度が他アンケートで使用中か）を画面上に示す。

営業日設定を変更すると作業日がずれるため、配員した時点では上限内だったアンケートどうしが後から同じ日に重なることがある。営業日の変更は正当な操作なので中止させず、重複を見逃せないようにする。

- 重複が発生している日は、月セルにその旨を示す。月セルは 1 行で溢れを切り落とすため、警告は行の先頭に置き、幅が狭い環境でも消えないようにする。切り落とされた内容は補足表示から読めるようにする。
- 重複が発生している日数を月の集計に表示する。どの日かは補足表示で確認できるようにする。
- 営業日設定の変更によって重複が発生した日があるときは、変更の直後に対象の日付を挙げて通知する。判定は重複日数の増減ではなく**日付の集合の差分**で行う。日数が同じまま別の日へ移った場合を見逃さないためである。
- 重複の解消は配員の見直しで行う。設定変更を理由に配員を自動で減らさない。

実績は「その会社に振られた量」であって処理能力の上限とは限らない。稼働率の低い会社は実力より小さく出るため、推定値であることを明示したうえで会社ごとに上書きできるようにする。上書きは Lv3 以上が行う。

必要枚数が全社を総動員した処理枚数を超えるアンケートは、増員では解決しない。人員不足とは区別して示し、納期区分または受注量の見直しが必要であることを伝える。

#### 4.5.3 増員の依頼

不足しているアンケートについて、Lv3 以上が各社のオペレーター管理者（Lv2）へ増員を依頼できる。依頼には対象アンケート、会期、納期区分、納期、作業期間、必要枚数、供給枚数、不足枚数を含める。送信すると対象アンケートを追加募集中とする。

募集状態は充足状態から自動で遷移させ、運営の手作業を要しない（`01_admin_common_ui.md` §7.4・2026-08-12 追加）。

- 不足（供給枚数 < 必要枚数）のアンケートは自動で「追加募集中」、充足したアンケートは自動で「募集完了」とする。
- 手動の締切・再開は例外操作として残す。不足を承知で打ち切った締切は運営の意思決定として維持する。充足時に付いた締切が営業日変更などで後から不足へ戻った場合は、自動判定（追加募集中）へ戻す。

- [ ] Lv2 でログインした場合、営業日設定の操作要素が表示されず、設定内容は参照できる
- [ ] Lv2 でログインした場合、人数を入力できるのは自社の行のみで、他社の行は参照のみとなる

### 10.4 狭い画面

- [ ] 幅を狭めると 1 日 1 行の縦並びへ切り替わり、曜日の見出し行が消える
- [ ] 営業日タブの行形式にアンケートが並ばず、会期のある日には「会期 N 件」が出る
- [ ] 行の左に日付と曜日、右にその日のアンケートが並ぶ
- [ ] 休業日・振替営業日が行の背景で区別できる
- [ ] 行内で日付を選択する操作とアンケートを選択する操作が分かれている
- [ ] 日付詳細領域がカレンダーの下へ積まれる
- [ ] 幅を戻すと 7 列のマス目へ復帰する
- [ ] どの幅でもページが横スクロールしない
