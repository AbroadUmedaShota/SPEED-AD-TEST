# クーポン管理 要件定義書

| 項目 | 値 |
| --- | --- |
| 対象画面 | `/admin/coupon` |
| 画面 ID | SCR-A-007 |
| 正本区分 | 本書を正本とする |
| owner | product |
| last_reviewed | 2026-07-31 |

## 1. 文書目的

- 本書は、クーポン管理の要件を定義する。
- 全画面に共通する権限、UI 規則、監査ログ、通知、用語は共通編を参照する。本書は本画面に固有の要件を扱う。
- 個別の請求へクーポンを事後適用する操作は本書の対象外とし、`15_admin_billing.md` §4.6 で扱う。

## 2. 画面概要

- クーポンの発行から効果の確認までを 1 画面で完結させる。
- 発行時に使用可能期限、割引率、使用可能回数を設定する。
- 発行済みクーポンがどのアンケートでいつ使われたかを利用履歴で確認する。
- 配布先の数だけコードを用意する場面では、共通の条件を決めて一度に複数のクーポンを作成する。

### 2.1 クーポン管理と請求管理の責務分担

| 画面 | 担当する範囲 |
| --- | --- |
| クーポン管理（本画面） | クーポンの発行・一括作成・編集、利用履歴の確認 |
| 請求管理（SCR-A-006） | 個別の請求へクーポン割引を事後適用する実行 |

## 3. 想定利用者と対象範囲

### 3.1 想定利用者

- 運営全体を管理する Lv3・Lv4。販促条件の設定と、発行したクーポンの効果確認を行う。

### 3.2 対象範囲

- クーポンの一覧・検索
- クーポンの作成・編集
- 使用可能期限、割引率、使用可能回数の設定
- クーポンの一括作成
- 利用履歴の確認

### 3.3 対象外

- 個別の請求へのクーポン適用（`15_admin_billing.md`）
- 請求金額の算出と補正（`15_admin_billing.md`）
- 利用者側でのクーポン入力（利用者向け画面で扱う）

## 4. 画面要件

### 4.1 共通構成

- ヘッダー、サイドバー、パンくずを表示する（`01_admin_common_ui.md` §2）。
- 画面タイトルを表示する。
- 画面は上から、検索条件、クーポン一覧の順に配置する。
- 一覧の上部に、クーポンの新規作成の操作を配置する。

### 4.2 一覧表示

各クーポンについて次を表示する。

| 表示項目 | 内容 |
| --- | --- |
| クーポン ID | クーポンを一意に識別する ID |
| クーポン名 | クーポンの名称 |
| コード | 利用時に入力するコード |
| 作成日 | クーポンを作成した日付 |
| 使用可能期限 | クーポンを使用できる期限。期限まで 1 ヶ月以内の行には「期限間近」、過ぎた行には「期限切れ」の識別表示を添える（間近の閾値は 2026-08-18 確定） |
| 割引率 | 適用する割引の率 |
| 使用可能回数 | 使用できる上限回数 |
| 使用回数 | 実際に使用された回数。使用可能回数に対する割合を併記する |
| メモ | クーポンに関する記録 |

- 割引率は整数の百分率で表示する（`01_admin_common_ui.md` §9）。
- 一覧はページングと表示件数の選択に対応する（`01_admin_common_ui.md` §4.3）。
- 各列で昇順・降順の並び替えができる。

### 4.3 検索

| 条件 | 種別 | 内容 |
| --- | --- | --- |
| クーポン ID | 検索 | 完全一致または前方一致で対象を絞り込む |
| クーポン名 | 検索 | 部分一致で絞り込む |
| コード | 検索 | 完全一致または前方一致で絞り込む |
| 作成日 | 検索 | 期間を指定して絞り込む |

条件をまとめて初期状態へ戻す操作を用意する。

### 4.4 クーポンの作成・編集

作成時および編集時に次を設定する。

| 項目 | 内容 |
| --- | --- |
| クーポン名 | クーポンの名称 |
| コード | 利用時に入力するコード。重複しない値とする |
| 使用可能期限 | クーポンを使用できる期限の日付 |
| 割引率 | 適用する割引の率 |
| 使用可能回数 | 使用できる上限回数 |
| メモ | クーポンに関する記録 |

- 保存操作で確定する。保存中はボタンを非活性化し、二重実行を防ぐ（`01_admin_common_ui.md` §7.3）。
- 既に使用されているクーポンの割引率・使用可能回数を変更した場合の、適用済み請求への影響は §11 で確定する。

### 4.5 利用履歴の確認

- クーポンごとに、使用された履歴を一覧で表示する。
- 各履歴について、使用日時、対象のアンケート ID、対象の会社名、適用した割引率、適用後の金額を表示する。
- 履歴から請求管理（SCR-A-006）へ遷移する。

### 4.6 クーポンの一括作成

配布先ごとに別のコードを渡す場面のために、共通の条件を決めて複数のクーポンを一度に作成する。作成は 3 段階で進める。

| 段階 | 内容 |
| --- | --- |
| 共通設定 | 作成件数、割引率、使用可能回数、使用可能期限、メモを指定する。ここで指定した値は作成するすべてのクーポンに共通で適用する |
| コードの確認 | 件数の分だけコードを自動で生成して一覧に示す。個々のコードとクーポン名は作成前に書き換えられる |
| 作成の実行 | 作成した件数を示し、作成したクーポンの一覧を CSV として出力できる |

- 作成件数は 1 以上の整数とする。上限は §11 で確定する。
- 自動生成するコードは既存のクーポンおよび同時に作成する分と重複しない値とする。重複の判定は §7.3 に従う。
- コードを手で書き換えた結果が重複する場合は、作成を実行せず該当行を示す。
- 作成の実行前であれば、共通設定へ戻って指定をやり直せる。
- 作成したクーポンは一覧の先頭（作成日の降順）に現れる。
- 作成の実行中はボタンを非活性化し、二重実行を防ぐ（`01_admin_common_ui.md` §7.3）。

### 4.7 追加要件（あったほうが良い）

| 要件 | 内容 |
| --- | --- |
| あとからクーポン適用 | 請求の確定後にクーポンを適用する。実行は請求管理（SCR-A-006）§4.6 で行い、本画面は対象クーポンの発行と利用履歴の確認を担う |

## 5. 通知

本画面の操作を起点とする通知・メールの発火はない（`03_admin_common_notifications.md` §2）。

## 6. 権限とデータ範囲

| 権限レベル | 扱い |
| --- | --- |
| Lv1 | 本画面へアクセスできない。サイドバーに項目を表示しない |
| Lv2 | 本画面へアクセスできない。サイドバーに項目を表示しない |
| Lv3 | 全範囲のクーポンを表示・操作できる |
| Lv4 | 全範囲のクーポンを表示・操作できる |

- 本画面は金銭情報を扱うため、Lv2 以下はテナント分離により到達しない（`00_admin_common_permissions.md` §3）。
- 権限判定はサーバー側で行う（`00_admin_common_permissions.md` §9.1）。

## 7. 状態と挙動

### 7.1 初期表示

- 検索条件は未入力の状態で表示する。
- 一覧の既定の並び順は作成日の降順とする。
- 表示件数の既定は 50 件とする。

### 7.2 使用可能な状態の判定

- 使用可能期限を過ぎたクーポン、および使用回数が使用可能回数に達したクーポンは、新たな適用の対象から外れる。
- 一覧では、使用できる状態にあるかを判別できるように表示する。

### 7.3 コードの重複

- コードは既存のクーポンと重複しない値とする。重複した値を保存しようとした場合はエラーを表示し、保存しない。

### 7.4 該当が 0 件の場合

- 一覧の位置に該当なしの旨を表示する。

## 8. 現行画面からの引き継ぎ

現行画面 `/admin/coupon` は次を備える。本画面はこれらの機能を引き継ぐ最低線とする。

| 現行の機能 | 本書での扱い |
| --- | --- |
| 一覧表示（ID／クーポン名／コード／作成日／使用可能期限／割引率／メモ） | §4.2。使用可能回数と使用回数を表示項目へ追加する |
| ID・クーポン名・コード・作成日による検索 | §4.3 |
| 作成・更新（使用可能期限／割引率／使用可能回数／メモ） | §4.4 |
| 利用履歴の確認 | §4.5 |

一括作成は現行画面 `/admin/coupon` に存在しない。§4.6 は新規に追加する要件として扱う。
2026-07-24 のたたき台監査では、根拠が B/C 列に遡れないとして一括作成を検討中の機能から下ろしていた（`docs/admin_tataki_H列検討中機能_由来対照_20260724.md`）。2026-08-04 のユーザー判断で本書へ戻す。アーカイブの画面設計仕様 `docs/アーカイブ/画面設計仕様admin_20260515/admin/40_admin_billing_and_rules.md` はクーポンの操作として一括作成を挙げており、前世代のモック `03_admin/modals/bulkCreateCouponModal.html` にも3 段階の実装がある。本書の §4.6 はこの 2 つを土台とする。

参考: 現行モック `03_admin/coupon-management.html` は、コード・名称の検索と、状態（有効／利用上限到達／利用停止／期限切れ）による絞り込みを持つ。この 4 値は前世代のモック`03_admin/src/coupon-management.js` の値集合と一致するが、現行画面 `/admin/coupon` の値集合は未確認である（§11 の #9）。モックは仕様上の正解とは扱わない。

## 10. 画面確認観点

モックアップ上で次を確認する。

- [ ] 一覧に §4.2 の項目が表示される
- [ ] 割引率が整数の百分率で表示される
- [ ] クーポン ID・クーポン名・コード・作成日による検索が機能する
- [ ] クーポンを新規作成し、使用可能期限・割引率・使用可能回数・メモを設定できる
- [ ] 既存クーポンを編集して保存できる
- [ ] 保存中はボタンが非活性化され、二重実行が発生しない
- [ ] 重複するコードを保存しようとするとエラーが表示され、保存されない
- [ ] 利用履歴に、使用日時・対象アンケート ID・会社名・割引率・適用後の金額が表示される
- [ ] 利用履歴から請求管理へ遷移できる
- [ ] 使用できる状態にあるクーポンと、期限切れ・使用上限に達したクーポンが一覧上で判別できる
- [ ] 一括作成で件数・割引率・使用可能回数・使用可能期限・メモを指定し、件数の分だけコードが生成される
- [ ] 生成されたコードとクーポン名を書き換えられ、重複するコードでは作成が実行されない
- [ ] 一括作成の実行後に作成件数が表示され、CSV を出力できる
- [ ] 一括作成で作成したクーポンが一覧の先頭に現れる
- [ ] 初期表示の並び順が作成日の降順である
- [ ] Lv2 以下でログインした場合、本画面の URL へ直接アクセスしても表示されない

## 11. 画面外の確認事項

| # | 項目 | 内容 |
| --- | --- | --- |
| 1 | 紐付け単位 | クーポンを顧客単位・アンケート単位・全体のいずれに紐付けるかを確定する。データモデルと適用時の検証条件が変わるため、他の確定に先立って決める。 |
| 2 | 使用可能回数の数え方 | 使用可能回数をクーポン全体の上限とするか、1 顧客あたりの上限とするかを確定する。#1 の紐付け単位と連動する。 |
| 3 | 使用中クーポンの編集 | 既に使用されているクーポンの割引率・使用可能回数を変更できるかを確定する。変更を許す場合、適用済みの請求へ遡及するかを決める。 |
| 4 | 一括作成の上限件数 | §4.6 の作成件数に上限を設けるかを確定する。設ける場合の値と、超えたときの表示を決める。 |
| 5 | 割引の計算方法 | 割引率のみとするか、定額割引も扱うかを確定する。端数処理の方法も併せて決める。 |
| 6 | 期限切れクーポンの扱い | 使用可能期限を過ぎたクーポンを一覧に残すか、既定の絞り込みから外すかを確定する。 |
| 7 | 利用者側での入力 | 利用者がコードを入力して自ら適用する経路があるかを確定する。ある場合、運営側の事後適用との重複適用を防ぐ条件を決める。 |
| 8 | 適用操作の記録 | クーポンの発行・編集と事後適用を監査ログの記録対象に加えるかを確定する。金銭に影響する操作であり、記録対象とする妥当性を判断する。`02_admin_common_audit_log.md` §9 の #7 と同一の論点であり、請求管理側の記録対象（`15_admin_billing.md` §11 の #5）と同時に確定する。 |
| 9 | 状態の値集合 | 現行画面 `/admin/coupon` が持つ状態の値集合を確認する。本書は有効／利用上限到達／利用停止／期限切れの 4 値を前提とするが、出所は前世代のモックであり現行画面では未確認である（§8）。 |
