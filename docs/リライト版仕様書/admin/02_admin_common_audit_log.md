# 管理者画面 監査ログ方針（共通編）

| 項目 | 値 |
| --- | --- |
| 対象 | 管理者画面 全画面 |
| 正本区分 | 本書を正本とする |
| owner | product |
| last_reviewed | 2026-07-31 |

## 1. 文書目的

- 本書は、管理者画面で行われた操作の記録方針を定義する。記録対象の操作、記録項目、閲覧方法、出力を扱う。
- 記録内容を表示する画面（監査ログ画面）の要件は `25_admin_audit_log.md` で扱う。
- 利用者向け画面の操作履歴は本書の対象外とする。

## 2. 方針

運営側が行った操作を「誰が、いつ、何に対して行ったか」の形で後から追跡できる状態を維持する。対象は運営側の操作のうち、顧客データ・金銭・アカウント権限に影響する操作とする。

ログは次の 2 系統で閲覧する。両者は同一のデータを参照し、抽出条件のみが異なる。

| 系統 | 場所 | 内容 |
| --- | --- | --- |
| 横断ログ | 監査ログ画面（サイドバーから遷移） | 全操作を時系列で確認する |
| 個別ログ | 各画面の詳細画面内 | その対象（ユーザー、アンケート）に関する操作のみを抽出して確認する |

個別ログの配置は画面ごとに次のとおりとする（オペレーター管理〈SCR-A-014〉は 2026-08-28 のモックレビューで個別ログを持たない構成へ変更。同画面での操作の記録は横断ログで閲覧する）。

| 画面 | 個別ログの配置 |
| --- | --- |
| ユーザー詳細（SCR-A-003） | 独立した詳細画面の内部 |
| アンケート詳細（SCR-A-005） | 独立した詳細画面の内部 |

## 3. 記録対象の操作

次の操作を記録対象とする。

| 操作 | 主な発生画面 |
| --- | --- |
| 代行変更（利用者に代わって行う設定変更） | ユーザー詳細、アンケート管理、アンケート詳細 |
| パスワードの管理者直接設定 | オペレーター管理、ユーザー詳細 |
| パスワード初期化メールの送信 | オペレーター管理、ユーザー詳細 |
| 権限レベルの変更 | オペレーター管理 |
| アカウントの有効化・無効化（利用者アカウントの停止を含む） | オペレーター管理、ユーザー管理 |
| 招待の実行・再送・キャンセル | ユーザー管理、ユーザー詳細、オペレーター管理 |
| 回答の削除 | アンケート詳細 |
| アンケートの削除 | アンケート管理 |
| 公開後の設問変更 | アンケート詳細 |
| アンケートの強制停止 | アンケート詳細 |
| 完了データの手動アップロード | アンケート管理 |
| グループの作成 | オペレーター管理 |
| 営業日設定の変更（定休日・個別休業日・振替営業日の追加と削除、CSV による一括取込） | 営業日カレンダー（2026-08-14 追加） |
| クーポンの作成・編集・事後適用（※要確定・§9） | クーポン管理、請求管理 |
| プレミアム契約状態の変更（※要確定・§9） | ユーザー詳細 |
| CSV・名刺画像などのデータ持ち出し | `01_admin_common_ui.md` §10 に定めるファイル出力を持つ全画面 |
| 管理者のログイン・ログアウト | 全画面 |

## 4. 記録項目

各レコードに次を記録する。

| 項目 | 内容 |
| --- | --- |
| 操作日時 | 操作を実行した日時（JST） |
| 操作者 | 実行したアカウントの識別子と表示名、権限レベル |
| 操作種別 | §3 の操作を識別する区分 |
| 対象 | 操作対象の識別子（ユーザー ID、アンケート ID、オペレーター ID など）と表示名 |
| 対象グループ | 操作対象が属するグループ |
| 理由 | パスワードの管理者直接設定で入力した理由 |

パスワードの管理者直接設定は理由の入力を必須とするため、理由を必ず記録する（`00_admin_common_permissions.md` §7.3）。

### 4.1 追加で記録する項目（あったほうが良い・※要確定・§9）

- 変更前の値と変更後の値
- 理由（パスワード直接設定以外の操作）
- 操作の成功・失敗の区別

## 5. 記録の取り扱い

- ログは追記のみとする。記録後の編集と削除は行わない。編集・削除の操作要素を画面に設けない。
- パスワードそのものは、平文・ハッシュのいずれの形でも記録しない。
- 操作が成立したにもかかわらず記録が欠落する状態は許容しない。実現方式は §9 の確認事項で確定する。

## 6. 閲覧権限

- 横断ログ画面の閲覧は Lv3 以上とする（`00_admin_common_permissions.md` §3）。
- 各画面の詳細画面または詳細モーダル内の個別ログは、その画面のアクセス権限とデータ範囲に従う。
- Lv2 に自グループ分の閲覧を許可するかは確定前とする（※要確定・§9）。

## 7. 出力

- 横断ログはファイル出力に対応する。出力形式と文字コードは `01_admin_common_ui.md` §10 に従う。
- 出力対象は、その時点で適用されている抽出条件（期間、操作種別、操作者、対象）の結果とする。
- ログの出力操作そのものも §3 の「データ持ち出し」として記録する。

## 8. 本番化要件

### 8.1 受け入れ基準

- [ ] §3 の各操作を実行した直後に、横断ログへ対応するレコードが 1 件追加される
- [ ] 同じ操作が、対象の詳細画面または詳細モーダル内の個別ログにも表示される
- [ ] パスワードの管理者直接設定のレコードに、入力した理由が記録されている
- [ ] ログレコードに対する編集・削除の操作要素が画面に存在しない
- [ ] Lv2 でログインした状態で横断ログ画面へ直接アクセスしても表示されない
- [ ] ログ出力ファイルに、抽出条件に合致するレコードがすべて含まれる

## 9. 画面外の確認事項

| # | 項目 | 内容 |
| --- | --- | --- |
| 1 | 保管期間 | ログをどこまで遡って保持するかを確定する。保持期間経過後の扱い（削除／アーカイブ）も併せて決める。 |
| 2 | Lv2 の閲覧許可 | Lv2 に自グループ分のログ閲覧を許可するかを確定する。許可する場合は横断ログ画面のアクセス範囲へ Lv2 を追加する。`00_admin_common_permissions.md` §10 の #6、`25_admin_audit_log.md` §11 の #2 と同一の論点であり、3 点を同時に確定する。 |
| 3 | 変更前後の値の記録 | §4.1 の追加項目を導入するかを確定する。導入する場合、対象操作と保存形式（差分／全体）を決める。 |
| 4 | 保存先 | ログを DB テーブルとファイルのいずれで保持するか、両方持つかを確定する。 |
| 5 | 記録漏れの検知 | 記録処理が失敗した場合に操作自体を失敗として扱うか、操作を成立させたうえで別途検知するかを確定する。 |
| 6 | 利用者側操作との統合 | 利用者が自分で行った変更と、管理者が代行した変更を同一のログで追えるようにするかを確定する。 |
| 7 | 金銭に影響する操作の記録対象 | §3 に ※要確定 を付した 2 行（クーポンの作成・編集・事後適用、プレミアム契約状態の変更）を記録対象とするかを確定する。`17_admin_coupon.md` §11 の #8、`11_admin_user_management.md` §11 の #3 と連動する。 |
