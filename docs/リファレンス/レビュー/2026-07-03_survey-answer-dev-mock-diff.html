回答画面改修向け dev / モック視覚比較

この資料は、回答画面改修時に「どちらへ寄せるべきか」「どこが比較不能か」を判断するための視覚比較資料。調査ログではなく、改修方針を決める読み手向けに整理している。

結論サマリー: 今回の比較で分かったこと

1. dev側は多設問IDへ差し替え済み dev id=392 を使用。11問構成で、自由記述・単一/複数選択・数値・日付時刻・手書き・名刺導線を確認できる。
2. モックは目標状態の候補 モックは16問・多入力タイプを確認できるが、実装済み仕様とは限らない。devと完全同一データではないため、設問数や文言差だけで仕様差とは断定しない。
3. 共通で判断できる範囲 表示枠、自由記述、選択肢系、名刺撮影/手入力、スマホ表示は左右比較できる。送信時挙動はdev側ボタン無効のため追加確認が必要。
4. 名刺撮影は優先判断が必要 入口とストレージ選択はほぼ揃う。カメラ分岐、OCR表示、最終ボタン文言は追加判断が必要。

改修優先度

P0: 仕様判断なしに実装するとブレるもの
  • 設問必須エラーと名刺不足モーダルの表示優先順位
  • dev id=392で送信ボタンが無効になる理由と、有効化条件
  • 送信導線を固定フッターにするか末尾配置にするか
P1: UI統一や文言修正で改善できるもの
  • 名刺撮影モーダルの文言、余白、ステップ表示の統一
  • 最終確認ボタン文言の統一
  • survey.tapToCapture や OCR言語: 日本語 (ダミー) の表示要否整理
P2: 追加ID/実機確認後でよいもの
  • 通常画像添付、手書き、日付、時刻、マトリクス系の詳細差分
  • mock側カメラ分岐の実機ブラウザ確認
  • Firefox、Edge、Safariでの見え方

次に必要な確認

  • dev側はid=392で多設問比較に近づけたが、通常画像添付と送信可能状態を確認できるアンケートIDが必要。
  • 実機スマホで名刺撮影、カメラ権限、通常画像添付を確認する。
  • 名刺手入力の保存後状態、名刺撮影の保存後状態、送信成功まで確認する場合はユーザー許可が必要。
  • 送信成功まで実行するかどうか、実データに影響する可能性があるため事前に対象環境と許可範囲を決める。
